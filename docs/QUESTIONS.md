## 答え方

- 各質問の **A** がおすすめです。`全部おすすめで` だけでも開発を始められます。
- 変えたい所だけ `Q4 は B`、`Q13 は 12色で名前なし` のように番号で教えてください。
- 選択肢に無い答えや「よく分からない」もそのままで大丈夫です。
- 質問は全部で 31 問です（要件の読み込みで出た論点 127 件から、要件に答えがある物と開発側で決めてよい物を外しました）。
- 後半の「聞かずに決めたこと」も、違和感があれば番号で教えてください。

## 開発を始める前に決めたいこと（5問）

データの持ち方や画面の骨組みに効くので、ここだけは先に答えてください。

### Q1. カレンダー全体（仕事／プライベートの切り替えボタン）

要件には「最初は仕事用のカレンダーを出し、切り替えボタンでプライベート用に切り替える」とあります。一方で、マンスリーのマス目は「4/3」と仕事とプライベートの両方の数を出し、ウィークリーとデイリーも仕事とプライベートを仕切って両方を出す、とも書かれています。両方がいつも見えているなら、切り替えボタンを押すと何が変わればよいですか？ 例: 11/10 のマス目が「4/3」の時にプライベートへ切り替えたら、「3」だけになるのか、「4/3」のまま「3」が濃くなるのか。

**決めないと困ること**: 4つのモードすべての画面の作りがここで決まります。「片方だけを出す」にすると、マンスリーの「4/3」やウィークリーの仕切りの書き方と食い違うので、作り始める前に決める必要があります。

- **A**（おすすめ）: 両方を見せたまま、「いま主に扱う側」を切り替える（選んだ側の数字が濃くなり、ウィークリーとデイリーでは上に来て、新しく入れる予定も最初からその側になる）
- **B**: 切り替えた側だけを見せる（プライベートにすると、マンスリーは「3」だけ、ウィークリーもプライベートの段だけになる）
- **C**: 切り替えボタンは無くし、いつも両方を同じように見せる

**おすすめ案の中身**: 1つ目。アプリを開くたびに仕事から始める（要件どおり）。切り替えはカレンダーの上の左端に「仕事｜プライベート」の2つのボタンで置き、4つのモードで共通にする。右の列（Task List など）は切り替えに関係なく両方を出す。職場で私用の予定を画面に出したくない場面が出てきたら、「プライベートを隠す」を後から足せる作りにしておく。

### Q2. Task List とカレンダーの連動（締め切り日の意味）

カレンダーの「締め切り日」は「開始日から締め切り日までの、何日にもまたがる予定」という意味ですが、Task List には開始日がありません。例えば 11/10 に、部長から口頭で頼まれた「見積もりを出す（締め切り 11/20）」を Task List に入れた時、カレンダーにはどう出せばよいですか？

**決めないと困ること**: 予定の持ち方の土台になります。期間として出すと、マンスリーの 11/10〜11/20 の11日間すべての数字が +1 され、その日の量が実際より多く見えます。また、ウィークリーでは何日にもまたがるカードは動かせないので、Task List から来たタスクはほとんど動かせなくなります。

- **A**（おすすめ）: 締め切り日の 11/20 だけの、1日の予定として出す
- **B**: 入れた日の 11/10 から締め切り日の 11/20 までの、期間の予定として出す

**おすすめ案の中身**: 1つ目。カードには小さく「〆」の印を付ける。ウィークリーでそのカードを別の日へ動かすと、Task List の締め切り日もその日に変わる。期間にしたい時は、カレンダーの詳細で開始日を前に足せば何日にもまたがる予定になる（Task List の左の欄には、終わりの日＝締め切り日を出す）。締め切り日を消すと、カレンダーからは消えて Task List にだけ残る。

### Q3. 予定の完了（何日にもまたがる予定）

何日かにまたがる予定の「完了」は、予定全体で1回ですか、それとも1日ごとですか？ 例えば「1/30〜2/3 研修」の1日目が終わった時、1/30 の分だけを完了にしたいことはありますか？ それとも、全部終わってから1回完了にすれば足りますか？

**決めないと困ること**: 1日ごとにすると、予定ごとに「どの日が済んだか」を覚える作りになり、マンスリーの −1、ウィークリーのグレー、Task View の出し方がすべて1日ごとになります。後から変えると作り直しになります。

- **A**（おすすめ）: 予定全体で1回（どの日のカードでチェックしても、期間全体が完了になる）
- **B**: 1日ごとに完了にできる

**おすすめ案の中身**: 1つ目。1日ずつ消し込みたい物は1日ずつの予定として入れ、詳細の「複製」で手早く作れるようにする。完了した日時は記録しておく。

### Q4. スマホの画面の並べ方

画面の並べ方は PC の分しか書かれていません。スマホは画面の幅が PC の3分の1ほどしかなく、大きなカレンダーの右に3つのリストを並べられません。スマホではどう並べますか？

**決めないと困ること**: スマホのすべての画面の骨組みになり、後から変えると作り直しになります。要件の「トップ画面にすべて表示」「どの画面でも常に画面右」はスマホでは書いてあるとおりにできないので、どう崩すかを決める必要があります。スマホで思いつきをすぐ書き留められるかどうかも、ここで決まります。

- **A**（おすすめ）: 縦に積む。上からカレンダー → Task List → Routine List → Favorite List。画面の上に「カレンダー｜Task 3｜Routine 2｜Favorite 12」の切り替えをいつも出し、1回押せばそこへ飛べる（NS のホームのスマホと同じ作り）
- **B**: 画面の下の「リスト」ボタンを押すと、3つのリストの面が横から出てくる（カレンダーは裏に残る）
- **C**: 画面の下のタブで「カレンダー」と「リスト」を切り替える

**おすすめ案の中身**: 1つ目。何も隠さないので「いちいち専用画面に行かない」考えを保てる。右上の MIM ボタンはスマホでもいつも出す。タブレットの横向きなど幅が十分ある時は、PC と同じく右の列に並べる。

### Q5. 繰り返しの予定

「毎週月曜 10:00 定例会議」「毎月25日 支払い」のように、日時の決まった繰り返しの予定をカレンダーに出したいですか？ 要件では、毎日・毎週…の決まった作業は Routine List に入れて右の列に出すだけで、カレンダーには出しません。予定の入力項目にも「繰り返し」はありません。

**決めないと困ること**: 本物の繰り返し（「毎週月曜」という決まりを1つ持ち、1回だけ動かす・1回だけ消すもできる）を入れると、予定の持ち方が大きく複雑になります。入れるかどうかは作り始める前に決めておきたい点です。

- **A**（おすすめ）: 繰り返しは作らない。代わりに詳細に「複製」を置き、「来週の同じ曜日へ」「何回分か」をまとめて作れるようにする
- **B**: 「毎週」「毎月」などの決まりを付けられる本物の繰り返しを作る
- **C**: いらない（複製も不要）

**おすすめ案の中身**: 1つ目。決まった会議は複製でまとめて作り、作った後は1回ずつふつうの予定として動かせる・消せる。日時の決まっていない習慣は Routine List に入れる、という住み分けにする。

## その機能を作る前に決めたいこと（13問）

### Q6. Task List とカレンダーの連動（「連動」の意味）

要件の「カレンダー側で詳細や件名の編集、完了チェックなどを入れた場合には消し込みとして連動される」は、どちらの意味ですか？ 例: Task List に入れた締め切り付きの「見積もりを出す」を、カレンダー側で「見積もりを出す（A社）」に直した時、Task List ではどうなればよいですか？

**決めないと困ること**: 2つ目の意味なら、完了とは別に「Task List から外した」という状態を持つ必要があります。Task List に何が残り、何が消えるかの見え方が変わります。

- **A**（おすすめ）: 同じ1件として両方に出る。カレンダーで件名を直せば Task List の表示も変わり、カレンダーで完了にすれば Task List でも消し込まれる（Task List 側で直した・完了にした時も同じ）
- **B**: カレンダー側で一度でも件名や詳細を直したら「カレンダーで管理することにした」とみなし、まだ完了していなくても Task List から外す

**おすすめ案の中身**: 1つ目。件名・依頼者・締め切り日・メモはどちらで直しても両方に出る。完了はどちらでチェックしても両方で完了になる。削除はどちらからでも両方から消えてゴミ箱へ入り、戻すと両方に戻る。締め切りの無いタスクに後から日付を決めてカレンダーに入れた時も同じく、完了するまで Task List に残る（外したい時は「…」から「Task List から外す」）。

### Q7. Task List（仕事／プライベートの印）

要件では「タスクは登録時に必ず仕事用とプライベート用のラベルを付ける」とあります。Task List に突発的な依頼を放り込む時も、仕事かプライベートかを付ける必要があります（締め切りを入れるとカレンダーの仕事かプライベートの段に出るため）。どう付けますか？

**決めないと困ること**: 「必ず付ける」と「雑に放り込む」がぶつかる所です。3つ目にすると、締め切りの無いタスクが仕事でもプライベートでもない状態になり、要件の「必ず付ける」から外れます。

- **A**（おすすめ）: 最初から「仕事」が付いていて、行の左の小さな印を押すとプライベートに切り替わる
- **B**: Task List に入れるたびに、仕事かプライベートかを選ぶ
- **C**: 最初は付けず、締め切りを入れてカレンダーに出す時に選ぶ

**おすすめ案の中身**: 1つ目（人から口頭で頼まれる突発の依頼は仕事が多いため）。ラベルの色は、仕事とプライベートそれぞれの「いつもの色」を自動で付け、カレンダーの詳細で変えられる。

### Q8. マンスリー（何日にもまたがる予定の数え方）

何日かにまたがる予定は、マンスリーのマス目のどの日に数えますか？ 例えば仕事の「1/30〜2/3 研修」（間に日曜の 2/1 がある）の場合です。

**決めないと困ること**: 「日ごとの量をひと目で見る」というマンスリーの狙いの中心です。毎日数えると、長い期間の予定が毎日の数を押し上げ、休みの日にも仕事の数字が出ます。1日だけ数えると、期間の途中の日が空いて見えます。

- **A**（おすすめ）: 期間中の毎日に +1 する。ただし仕事の休みの日には、仕事の複数日の予定は数えない（2/1 には数えない）
- **B**: 期間中の毎日に +1 する（休みの日も数える）
- **C**: 始まりの日（1/30）だけに数える
- **D**: 締め切りの日（2/3）だけに数える

**おすすめ案の中身**: 1つ目。完了にすると、期間中のすべての日から −1 する。休みの日に出勤する時は、その日を「出勤」に変えれば数に入る。

### Q9. 仕事の休み（自動で付けるか）

「仕事の休み」は全部手で付けますか？ それとも土日・祝日は自動で休みにしますか？ ふだんの働き方を教えてください（例: 土日祝が休みの会社／シフト制で休みが毎月変わる／土曜出勤がある）。土日祝が休みなら、毎週土日に手でチェックを付けるのは手間です。逆にシフト制なら、自動で付くのは邪魔になります。

**決めないと困ること**: 休みを「1日ずつの印」だけで持つか、「いつも休みの曜日」という決まりと日ごとの例外で持つかが変わります。マンスリーの数え方にも効きます。

- **A**（おすすめ）: 設定で「いつも休みの曜日」（初めは土・日）と「祝日は休み」を決めて自動で付け、日ごとに「この日は出勤」「この日は休み」と上書きできる
- **B**: 自動では付けず、全部手で付ける
- **C**: 曜日だけ自動で付け、祝日は手で付ける

**おすすめ案の中身**: 1つ目。決まりを後から変えても、日ごとに付けた印は残す。

### Q10. ウィークリー（スマホでの並べ方）

ウィークリーは「日曜始まりの7日を横に並べる」作りですが、スマホの幅では1日が指1本分ほどしかなく、カードの件名が読めず、指で動かすのも難しくなります。スマホではどう並べますか？

**決めないと困ること**: スマホでのカードの動かし方（上下へ動かすか、左右へ動かすか）と画面の作りが変わります。要件の「Windows/Android/iOS で同じように作動する」を「操作が同じなら、並び方は画面の幅で変えてよい」と考えてよいかの確認でもあります。

- **A**（おすすめ）: 日曜から土曜までを上から下へ縦に並べ、各日の行の中を左＝仕事・右＝プライベートに仕切る
- **B**: 横に並べたまま、3日分ずつ横にずらして見る
- **C**: 7日を横に並べたまま、件名を数文字で切って出す

**おすすめ案の中身**: 1つ目。PC やタブレットの横向きなど幅が広い時は、要件どおり7日を横に並べ、仕事とプライベートは上下に仕切る。

### Q11. ウィークリー（スマホでカードを動かす方法）

スマホでは指でなぞると画面のスクロールになるので、カードを別の日へ動かす方法を決める必要があります。どれがよいですか？ なお、iPhone のブラウザは振動で知らせることができないので、つかんだ時はカードが少し浮く見た目だけで知らせます。

**決めないと困ること**: スクロール、カードを押す（詳細を開く）、完了のチェック、動かす、をはっきり押し分けられる必要があります。NS にはカードをドラッグする仕組みが無く、DS で新しく作る部分です。

- **A**（おすすめ）: カードを少し長押し（0.3〜0.5秒ほど）すると浮き上がり、そのまま指を動かして別の日へ移す。すぐ指を動かした時はふつうのスクロールになる
- **B**: カードの端に小さな「つまみ」を付け、そこを持てばすぐ動かせる（つまみ以外をなぞるとスクロール）
- **C**: スマホではドラッグせず、詳細で日付を変える

**おすすめ案の中身**: 1つ目。軽く押すと詳細が開く。ロック中・複数日のカードは長押ししても持ち上がらない（小さく揺れるだけで、知らせの文は出さない）。動かした直後だけ、画面の下に「11/12 へ移しました［元に戻す］」を数秒出す。Android は軽く振動する。PC はマウスでそのままドラッグする。

### Q12. ウィークリー（何日にもまたがる予定の見え方）

何日かにまたがる予定は、ウィークリーでどう見せますか？ 例: 仕事の「11/9(月)〜11/11(水) 出張」。

**決めないと困ること**: ウィークリーのカードの並べ方が大きく変わります。帯にすると、日をまたいでカードの高さをそろえる仕組みが要ります。

- **A**（おすすめ）: PC では Google カレンダーのように、日をまたぐ1本の横長の帯にする（仕事・プライベートそれぞれの段のいちばん上）。スマホの縦並びでは、各日に同じカードを「11/9〜11/11」の印付きで出す
- **B**: どの画面でも、期間中の各日に同じカードを1枚ずつ出し、「11/9〜11/11」と添える

**おすすめ案の中身**: 1つ目。週をまたぐ予定は、その週に入っている日だけを出し、端に「‹」「›」で続きを示す。動かせないことは小さな印で示す。どの日の分を押しても、同じ予定の詳細が開く。

### Q13. 予定の入力（時刻のある、何日にもまたがる予定）

何日かにまたがる予定に時刻を入れた時の意味を決めてください。例えば「1/30〜2/3、10:00〜15:00」は、どちらですか？

**決めないと困ること**: デイリーの右（時刻のあるタイムスケジュール）と左（時刻なしのリスト）のどちらに、どの日に出すかが変わります。

- **A**（おすすめ）: 1/30 の 10:00 に始まり、2/3 の 15:00 に終わるひと続きの予定（出張・旅行のような物。締め切り日の「何時まで」としても使える）
- **B**: 毎日 10:00〜15:00 の予定（5日間の研修のような物）

**おすすめ案の中身**: 1つ目。デイリーでは、初日は 10:00 から、最終日は 15:00 までをタイムスケジュールに出し、間の日は左のリストに「〜2/3 15:00」と添えて出す。毎日同じ時間の物は1日ずつの予定として入れる（「複製」で手早く作れる）。

### Q14. ラベルカラー（色の数と名前）

ラベルの色は何色くらい欲しいですか？（Google カレンダーの予定の色は11色です）。また、色に名前を付けて意味を持たせたいですか（例: 水色＝会議、黄色＝締め切り）、それとも色を選ぶだけでよいですか？

**決めないと困ること**: 色をどう覚えておくかが決まり、後から変えにくい所です。自分で色を作れるようにすると、ホワイト・ダーク・ディープダークのどれでも読みやすくするのが難しくなり、ディープダークで灰色に変えることもできなくなります。後で作る Claude からの書き込みでも、名前で色を指せると便利です。

- **A**（おすすめ）: パステル系の決まった24色（12の色合い×薄め・濃いめ）から選ぶ。名前は付けたい時だけ設定で付けられる（全端末で同じ）
- **B**: 決まった12色ほどから選ぶ（名前なし）
- **C**: 自分で好きな色を作って足せる

**おすすめ案の中身**: 1つ目。仕事とプライベートで同じ24色を使う。色を選ばずに入れた時の色は、仕事・プライベートごとに設定で決められる（初めは仕事＝青み、プライベート＝桃色）。

### Q15. Routine List（「いつやるか」の指定）

ルーティンに「いつやるか」の指定は要りますか？ 例: 毎週「月曜」のゴミ出し、毎月「25日」の振込、毎日だけど「仕事の日だけ」の日報、毎週「3回」のジム。

**決めないと困ること**: 指定を持たせると、ルーティンに曜日・日付・回数の情報が要り、日によって表示も変わります。指定しなければ「期間の中で1回チェック」だけで済み、ずっと単純になります。

- **A**（おすすめ）: 指定なし。期間の中で1回チェックすれば済み（「月曜 ゴミ出し」のように名前に書いて使う）
- **B**: 曜日や日付の目安を小さな文字で添えられる（表示や済みの決まりは1つ目と同じ）
- **C**: 曜日・日付・回数をきちんと指定でき、その日だけ出す・回数で数える

**おすすめ案の中身**: 1つ目。2つ目は後から足せる作りにしておく。どの場合も通知やアラートは出さない（要件どおり）。

### Q16. MIM（メモの形）

MIM は「1枚の大きなメモ」ですか、それとも「メモを何枚も作れる」形ですか？ 何枚も作る場合、1枚は「題名＋本文（自由に書く）」でよいですか？ 例:「会社の VPN」という題名の1枚に、URL・ID・パスワード・つなぎ方の手順をまとめて書く。

**決めないと困ること**: QR にする単位、パスワードを伏せる仕組み、探し方、MIM の持ち方がすべてここで決まります。

- **D5** 【データ】ラベルの色は、データには「色の名前（番号）」だけを持ち、実際の色は外観ごとに決める（ディープダークで灰色にできるように）。色の名前付けも全端末で同じになるようデータとして持つ。
- **D6** 【データ】すべての記録に「作った日時・完了した日時・誰が作ったか（手で入力／貼り付け／コネクタ）・どの AI か」を持たせ、データの形の版も NS と同じ仕組みで1から始める（後でコネクタや貼り付けを足すため）。
- **D7** 【データ】ルーチンのチェックは「チェックした日付」を全部記録し、「今の期間の中にチェックした日があるか」で済みを決める。0時に一斉に外す書き込みはしない（どの端末で開いても同じ結果になり、2台で食い違わない）。記録を見る画面はまだ作らず、昨日の分を後からチェックする操作も作らない。
- **D8** 【データ】MIM はほかのデータとは別の表に置き、後で作るコネクタからは読めない決まりにする。
- **D9** 【データ】メモは文字数の制限なし（長い時は NS と同じく分けて保存する）。データは消さずにずっと残し、何年分も溜まっても新しい端末での最初の受け取りが無料枠に収まるよう、過去の月をまとめて持つ工夫を最初から入れる。同じ日の中の並び順を覚える項目も持っておく（後で手の並べ替えを足せるように）。
- **D10** 【同期】同期と競合の決まりは NS と同じにする（題名やチェックのような短い項目は項目ごとに合わせ、メモなどの長い文章が両方で変わっていたら両方を残してつなぐ。削除と編集が重なったら削除を優先し、編集した内容はゴミ箱に控える。同期するのは1つのタブだけ）。ヘッダーに同期の状態（同期済み・未送信など）を出す。休みの決まりやラベルの名前も同期する。
- **D11** 【部品】ドラッグは @dnd-kit/react（版を固定する）、祝日は @holiday-jp/holiday_jp（2050年まで内蔵・ネット不要）、QR は uqr（端末の中だけで作り、パスワードを外へ送らない）を使う。
- **D12** 【祝日】祝日（振替休日・国民の休日を含む）はアプリの中に持ち、外部のカレンダーとはつながない。毎年2月ごろ（翌年の春分・秋分が発表された後）に部品を新しくして公開し直す。祝日名は PC のマンスリーと、ウィークリー・デイリーの日付の横に小さく出し、スマホのマンスリーとイヤーは赤い日付だけにする。
- **D13** 【ゴミ箱】削除した物は NS と同じく30日ゴミ箱に入れ、元の場所へ戻せる。予定と MIM のメモは消す前に確かめ、リストの項目とルーチンは確かめずに消して「削除しました［元に戻す］」を数秒出す。削除は「…」メニューから行い、横に払って消す操作は作らない。ゴミ箱は設定から開く。
- **D14** 【取り消し】ドラッグで日を移した・チェックした直後は、画面の下に［元に戻す］を数秒だけ出す（音や端末への通知は出さない）。文章の入力は入力欄の元に戻す（Ctrl+Z など）に任せる。
- **D15** 【バックアップ】NS と同じく、設定に全データのファイル書き出しと復元を置く。しばらく書き出していない時は、設定の画面の中で一言だけ知らせる（トップ画面には出さない）。
- **D16** 【外観】外観は「端末の設定に合わせる・ホワイト・ダーク・ディープダーク」の4つから選べ、NS と同じく端末ごとの設定にする（同期しない）。アプリの部分は白・灰・黒を基本にして色はラベルのパステルにまかせ、DS の青は「今日」の印・主なボタン・選んでいる所にだけ控えめに使う。土曜は薄い青、日曜・祝日は薄い赤で、DS の青とは濃さを変える。
- **D17** 【部品の見た目】ボタン・入力欄・小さな画面（ダイアログ）・細い線のアイコン・動きの速さ・各端末の標準の書体などは NS に揃える。DS だけにするのは、カレンダーの見た目・パステルのラベル・青・広めの余白。
- **D18** 【起動アニメーション】NS のグリッチの仕組みを使い、流れは「青いレーザーがちらつく → 点で描いた閉じた日記帳が現れる → 表紙が開き、ページに月のカレンダーのマス目が点で灯る → 点の字の『Diary Studio』が現れる」にする。色はどの外観でも青（ホワイトは白地に濃い青、ダークは黒地に明るい青、ディープダークは黒地に暗い青）。長さは2秒ほど、押すとすぐ消える、ウインドウやタブを開いた最初の1回だけ、設定でオフにできる、端末の「視差効果を減らす」がオンの時は動かさない（NS と同じ）。
- **D19** 【アイコン】NS と同じ黒地に光る点の字で、字を「DS」、点の色を明るい青（NS の緑と同じくらいの明るさ）にする。NS と並べても字と色で見分けられる。
- **D20** 【起動直前】ホーム画面から開いた時に端末が一瞬出す無地の画面は Web アプリでは消せないので受け入れ、地の色を NS と同じ黒にしてアニメーションへつなげる。
- **D21** 【画面の枠】ヘッダーは左に DS のアイコンと名前、右に同期の状態 → 設定の歯車 → いちばん右に「MIM」ボタン。MIM と Task View は要件どおり右の列を残したまま、カレンダーの所に開く（「カレンダーに戻る」付き）。設定の画面だけは別のページ。スマホでは MIM と Task View は全画面で開く。ブラウザやスマホの「戻る」で1つ前の画面・モードへ戻れる。
- **D22** 【画面の幅】幅が広い時（目安 900px 以上）は PC と同じ2列（右の列は 300px ほどで固定し、幅をドラッグで変える仕組みは付けない）。タブレットの縦持ちほどの時はカレンダーの下にリスト。スマホの幅は質問の答えの並びにする。
- **D23** 【カレンダーの操作の列】カレンダーの上に1列並べる。左から「仕事｜プライベート」「‹ 2026年11月 ›」「今日」、右寄せで「年｜月｜週｜日」「休み」「＋ 登録」「Task View」（Task View は要件どおりイヤーとマンスリーだけ）。そのモードに無いボタンは消すが、ほかのボタンの位置は動かさない。モードを替えても見ている日を引き継ぐ。ウィークリーの日付の見出しを押すとその日のデイリーへ。スマホではイヤー・マンスリー・デイリーで左右になぞると前後の期間へ移る（ウィークリーはカードの操作とぶつかるのでボタンだけ）。
- **D24** 【マンスリー】マス目は左が仕事・右がプライベートの数で、それぞれの色で出す。片方が0なら薄く「0」、両方0の日（何も無い日も、全部完了した日も）は何も書かない（要件どおり数字だけ）。PC は数字ごとに押し分け、押した側を主にしてその日のデイリーを開く。スマホはマス目が小さいので、どこを押してもその日のデイリーを開く。
- **D25** 【イヤー】予定のある日に、仕事とプライベートで色違いの小さな●を付ける（両方なら2つ）。全部完了した日は●を薄くする。休みは地を薄く塗り、祝日は赤い日付。どこを押しても要件どおりその月のマンスリーへ移る。
- **D26** 【ウィークリー】PC では仕事とプライベートの段を上下に分け、主に扱う側を上にする。段の高さは半分ずつで、多い時はその段の中でスクロールする。カードは件名（2行まで）・時刻・鍵の印・期間・✓を出し、依頼者とメモは詳細で見る。同じ日の中は、複数日の予定 → 時刻のある予定（時刻の順）→ 時刻なし（入れた順）→ 完了した物の順。手での並べ替えは最初は作らない。
- **D27** 【ウィークリー】要件の「ドラッグで日付を入れ替えて」は「カードを別の日へ移す」と読む（カード同士の日付の交換はしない）。仕事とプライベートの段をまたいでは置けない（要件どおり）。時刻のある予定は時刻を保ったまま日だけ変わる。週の外へはドラッグで移さず、詳細で日付を変える。
- **D28** 【デイリー】PC は左（時間指定なし）と右（タイムスケジュール）を 4:6 に分け、スマホは上に時間指定なし・下にタイムスケジュールを積む。何日にもまたがる予定は、左のリストに期間中毎日、期間を添えて出す。タイムスケジュールは0時〜24時で、開いた時は今の時刻の少し前（今日以外の日は朝7時）から見せ、今の時刻に横線を引く。重なった予定は横に並べ、開始時刻だけの予定は30分の枠で出す。仕事とプライベートが混ざるので、予定の右上に小さな線のアイコン（仕事＝かばん、プライベート＝家）を付ける。枠をなぞって時刻を変える操作は最初は作らない。
- **D29** 【完了】完了のチェックは詳細の中に加えて、ウィークリーのカードの左端の小さな丸、デイリーのリストの行の前の●、タイムスケジュールの予定の上でも直接押せる（もう一度押すと戻る）。見え方は要件どおり（ウィークリーは左の辺だけ色を残してグレー、デイリーのリストは斜線）。書かれていない所（タイムスケジュール・Task View）も斜線とグレーにそろえ、どの外観でも小さな✓を足して色の濃さだけに頼らない。
- **D30** 【ロック】要件どおり、ロックはウィークリーでドラッグできなくするだけで、詳細ではいつでも直せる。ロックのオン/オフは詳細に置き、カードに小さな鍵の印を出す。
- **D31** 【予定の登録】各日・各段に「＋」を置き、件名だけ打って Enter で入れられる（日付と仕事/プライベートは押した場所で決まる）。デイリーのタイムスケジュールの空いた所を押すと、その時刻で入力が始まる。「＋ 登録」ボタンでは全部の項目の画面を開く（日付はデイリーならその日、ほかは今日）。細かい項目は後でカードを押して足す。
- **D32** 【予定の登録・詳細の画面】PC は画面の真ん中の小さな画面、スマホは下からせり上がるシートで、カレンダーの上に重ねて開く（閉じれば元の画面のまま）。上から件名 → 仕事/プライベート → 日付（〜締め切り日）→ 時刻を見せ、ラベルカラー・依頼者・ロック・メモは「詳しく」の中に入れる。必ず入れるのは件名・日付・仕事/プライベートの3つ（日付と仕事/プライベートは開いた場所で最初から入っていて、後から詳細で変えられる）。新しい予定は［登録］（Ctrl+Enter でも）で確定し、今ある予定の詳細は直したそばから自動で保存する（NS のメモ・アイデアと同じ）。
- **D33** 【予定の入力の細かい決まり】入力欄の名前は要件どおり「締め切り日」で、「空なら1日だけ」と添える。開始時刻だけは入れられ、終了時刻だけは不可。終了が開始より前なら翌日までと読む。時刻は5分刻みで選べ、打てば1分単位も入る。開始日を締め切り日より後にしたら、締め切り日もそろえて1日の予定にする。メモの URL は押せるリンクにし、書式は付けない。日が過ぎても完了していない予定は動かさず、知らせも出さない（マンスリーの過去の日に残る数字が目印になる）。
- **D34** 【通知】予定の時刻の知らせ（スマホへの通知・音・アイコンの数字）は出さない（要件の「アラートが鬱陶しい」という考えに合わせる）。後から欲しくなった場合は、知らせを送る仕組みを別に用意する大きな追加になる。
- **D35** 【年の区切り】イヤーモード・その年の Task View・ルーチンの「年次」は1月〜12月、「四半期」は1・4・7・10月の1日で切り替え、「毎週」は日曜（カレンダーと同じ）、「毎日」は0時（要件の「次の日になると」どおり）で切り替える。年度や朝4時の切り替えが必要になったら、後から設定に足せる作りにしておく。
- **D36** 【Task View】PC は左に仕事・右にプライベート、スマホは上の「仕事｜プライベート」で切り替える。イヤーは「1月」「2月」…の見出しで区切り、各月の中は日付の順。何日にもまたがる予定は開始日で並べ、月をまたぐ物は両方の月に期間付きで出す。完了した物は✓と斜線。行を押すと詳細が開き、Task View から離れずに直せる。検索は件名・依頼者・メモをまとめて探し、全角と半角・大文字と小文字は同じとみなす（NS の資料の検索と同じ）。ゴミ箱の物とルーチンは出さない。
- **D37** 【Task List】1行は要件どおり左から「締め切り日｜依頼者｜要件」。入力欄に要件を打って Enter で足し、締め切り日（「今日・明日・今週金曜・日付を選ぶ」）と依頼者は横の小さなボタンで任意に足す。締め切りは日付だけで、時刻はカレンダーの詳細で入れる。依頼者は前に入れた名前を候補に出す。要件が2行以上なら、1行目を件名・2行目からをメモとして扱う。スマホでは要件を大きく、その上に「11/15・田中さん」を小さく出す2行にする。
- **D38** 【Task List】並びは締め切りの近い順（同じ日は入れた順）、締め切り無しはその下に新しい順。締め切りを過ぎた物は日付の字だけ淡い赤、今日の物は日付を太字にする（通知や赤い数字の印は出さない）。仕事とプライベートは混ぜて出し、行の左の小さな印で見分ける。Task List に出るのは Task List から入れた物だけ（カレンダーで入れた予定は、詳細の「Task List にも出す」をオンにした時だけ）。
- **D39** 【Task List → カレンダー】締め切り無しのタスクは、「…」メニューの「日付を決める」でカレンダーに入れられる（その日1日の予定になる）。PC では Task List の行をカレンダーの日へドラッグしても入れられる。
- **D40** 【Favorite List】1項目は内容の入力欄1つだけ（改行できる・文字数の制限なし。NS のアイデアと同じ）。2行以上なら1行目を少し太く、URL は押して開けるリンクにし、長い物は3行まで見せて「続き」で全部。足した日時は自動で記録する。分類や仕事/プライベートの区別は付けない（予定ではないため。カスタマイズの要素も増やさない）。新しい項目はいちばん上に足し、手で並べ替えられる（PC はドラッグ、スマホは長押し）。「…」メニューに「予定にする」（件名を入れた登録の画面が開く。元の項目は残る）と「Task List へ移す」を置く。
- **D41** 【Routine List】グループの順は毎日 → 毎週 → 毎月 → 四半期 → 年次で固定。1つのボタンで「すべて開く／すべて畳む」を切り替える（要件の「すべて開くボタン」）。グループの中は手で並べ替えでき、新しい項目は末尾に足す。項目の無いグループは見出しを淡く出してそこから足せる。見出しには今の期間（例:「毎週 11/8〜11/14」）と「3/5」のような済んだ数を淡く出す。ルーチンはカレンダーの数字にも Task View にも出さない。
- **D42** 【リスト共通】各リストのいちばん上に入力欄をいつも出し、打って Enter で続けて足せる（日本語の変換中の Enter では足さない。書きかけは端末に控えて消えないようにする）。項目の文字を押すとその場で直せ、詳しい内容は右の列の上に小さな画面を重ねて開く（別の画面へは移らない）。保存ボタンは置かず自動で保存する。畳んだ・開いた状態は端末ごとに覚える（NS のアイデアの仕切りと同じ）。
- **D43** 【MIM】一度開いた端末なら電波が無くても読める（端末の中にも保存する）。MIM の画面に「印刷」を置き、特に大事なメモは紙にも控えられるようにする。Google アカウントのパスワードを MIM だけに置かないよう、画面で一言案内する。
- **D44** 【iPhone】iPhone は Safari の「ホーム画面に追加」で使う前提にし、設定に追加の手順の案内を置く（NS の案内を流用する）。入力中にキーボードが入力欄を隠さないよう、NS の Web 版の対策を参考にする。
- **D45** 【キーボード】PC だけ最小限のショートカットを付ける: N（新しい予定）、← →（前後の期間）、T（今日）、Esc（閉じる）、Ctrl+Enter・⌘+Enter（登録）。文字を入力している間は効かない。
- **D46** 【見出しの言葉】領域の見出しは要件どおり英語（Calendar・Favorite List・Task List・Routine List・MIM・Task View）にし、下に小さく日本語を添える。ボタンや説明の文は日本語（モードは「年｜月｜週｜日」）。カレンダーに入れる物は画面では「予定」、Task List の物は「タスク」と呼び分ける。
- **D47** 【ほかのアプリからの取り込み】スマホの「共有」から DS へ直接送る機能は最初は作らない（Android ではできるが iPhone ではできないため）。コピーして、すばやい追加の欄に貼る。Android 向けは後から足す候補にする。
- **D48** 【AI の書き込み】後で作るコネクタは NS と同じく「足すだけ」にする（書き換え・チェック・削除はしない。削除は作者が頼んだ時だけゴミ箱へ移す依頼にする）。Claude が足した項目には小さな「Claude」の印を出し、同じ内容を2回足しても1件にする。書き込み先は要件どおり予定とやりたいことで、Task List（予定と同じデータ）も受け付けられる形にしておく。サーバーは NS と同じく無料のプランで作り、「受け付ける AI の一覧」を持たせて、後から Perplexity などを足せるようにする。
## 調査の要点（2026-11-10 時点）

- **NS から流用できる物**: 端末に保存してから Firebase で同期する仕組み（電波が無くても使える）、外観の切り替え、起動アニメーションの仕組み、アプリアイコンの作り方、線のアイコン、画面の部品、ゴミ箱、バックアップ、テストの土台。iPhone・Android の専用アプリ（Capacitor）の部分は外します。いちばん大きな作業は、端末内のデータベースの部分から小説専用の処理を外すことです。
- **Firebase**: NS とは別のプロジェクトを、無料のプラン（カード登録なし）で作ります。無料枠は1日に書き込み2万回・読み取り5万回・保存 1GiB で、個人のスケジューラには十分です。
- **ファイル保存**（Q26）: Firebase のファイル置き場は、今は従量課金のプラン（カード登録）でないと使えません。カード無しなら、予定などと同じ所に小分けして入れる方式（1つ10MBほどまで）が第一候補です。
- **QR コード**（Q25）: 小さくて依存の無い部品（uqr）を使います。日本語は標準の読み取りやすさで777字が上限、楽に読めるのは100字ほどです（手元で実際に作って読み取って確かめました）。
- **祝日**: 2050年までの祝日を内蔵した部品（@holiday-jp/holiday_jp）を使い、ネットが無くても判定できます。毎年、翌年の祝日が確定したら更新して公開し直します。
- **ドラッグ＆ドロップ**（Q11）: @dnd-kit/react を使います。スマホでは「少し押し続けると掴む・すぐ動かすとスクロール」が標準の動きです。

- **AI 連携**（Q29・Q30）: 自分で作った書き込みの仕組み（コネクタ）に個人で直接つなげるのは、Claude（無料プランでも1つ）と Perplexity（Pro 以上のブラウザ版。2026年3月から。スマホアプリは不明）です。ChatGPT は会社向けのプラン（1人でも月40〜50ドルほど）が要り、Gemini は日本で使えるか不明、Copilot は個人ではできません。どの AI でも使える方法として、NS の「Claude に頼む（手動）」と同じ貼り付け方式を提案しています。
