# Diary Studio 仕様書

個人用のスケジューラー「Diary Studio」（DS）の仕様。Web アプリ（PWA。React + TypeScript + Vite）として作り、Windows の PC・Android・iPhone のブラウザ／ホーム画面アプリで同じように動く。データは端末の中（IndexedDB）に置き、Firebase で自分の端末どうしを同期する。

### 用語

| 言葉 | 意味 |
|---|---|
| 項目（`items`） | カレンダーの予定と Task List のタスクを1つの表で持つ記録。画面ではカレンダーの物を「予定」、Task List の物を「タスク」と呼ぶ（D46）。同じ1件が両方に出ることがある（D3・Q6） |
| 区分（`kind`） | 仕事（`work`）／プライベート（`private`）。すべての項目に必ずどちらかが付く（要件・Q7） |
| 段 | 画面の中で仕事とプライベートを分けた領域。並びはいつも仕事が先（上・左）、プライベートが後（下・右）（Q1）。画面の領域の意味の「段」はこれだけ（複数日の予定を並べる行は「レーン」と呼んで分ける） |
| レーン | ウィークリーで、複数日の予定を並べる横の行（S の縦の並びでは縦の列）。週ごと・区分ごとに割り付ける（7.8） |
| 開始日・締め切り日 | 項目の日付（`start`・`due`）。カレンダーに出る範囲＝「期間」は 6.3 の決まりで決まる |
| 生まれ（`origin`） | 項目をカレンダーで入れたか（`calendar`）、Task List で入れたか（`list`）。カレンダーに出る条件が違う（6.3） |
| 複数日の予定 | 期間が2日以上の項目 |
| 休み | 自分で付けたシフトの休みの日（Q8・Q9）。祝日とは別 |
| 土台の色 | 区分の色。仕事＝青、プライベート＝ピンク（Q14）。カードの地・リストのマーカー・数字に使う（4.3） |
| ラベル・ラベルの色 | 項目ごとに選べる24色の印（Q14・I3）。選ばなくてもよい。カードの左の一辺・行頭の●・線に使う（4.3） |
| 完了／済み | カレンダーの予定は「完了」、3つのリストは「済み」と呼ぶ。データはどちらも `done` |
| 幅 S・M・L | 画面の幅の区分（3.2） |
| 見ている日 | カレンダーが今どの日を中心に出しているか。モードを替えても引き継ぐ（D23） |

## 1. コンセプト

- **直感的に、雑に扱えるスケジューラー**（要件）。いちいち専用の画面へ行かずに、見ている場所でそのまま足す・直す・消し込む。
- **トップ画面にすべて**（要件）: 起動アニメーションの後のトップ画面に Calendar・Routine List・Task List・Favorite List・MIM のボタン・Task View のボタンがすべて出ている。
- **思いつきをすぐ留める**（要件）: 3つのリストのいちばん上にいつも入力欄があり、打って Enter で足せる（D42）。Notion のような大がかりな作りや、覚えることの多い設定は入れない。
- **知らせない**（要件・D34）: 通知・音・アイコンの数字・アラートは出さない。済んでいない物は、画面に残る数字や色で静かに分かるだけ。
- **仕事とプライベートをいつも並べる**（Q1）: 切り替えずに、1つの画面の中で段を分けて両方を出す。
- **静かな見た目**（要件・Q18・Q24）: ギラつかないパステルで、ダークの外観を基準に色を作る。参考の手帳のような、等幅の数字・細い罫線・大きく淡い数字のミニマルな見た目にする（4.）。
- **使う人と端末**（Q28）: 作者1人。自分の Windows の PC と自分のスマホだけで使う（職場でも自分の端末）。外部のカレンダーとはつながない（要件）。

### 2.4 データの置き場所と同期

NS 2.x の同期をそのまま使う（D10・NS SPEC-2.md の 3.）。

- **画面は端末の中のデータだけを見る**。電波が無くても、ログインと同期以外のすべての機能が使える。
- **クラウドの形**: 1つの記録 = 1つの文書 `users/{uid}/records/{表名}:{id}`。中身は `json`（キーの順をそろえた JSON）・`hash`（指紋）・`updated`（サーバー時刻）・`device`（書いた端末の ID）・`deleted`（削除の印）・`chunks`（25万字を超える JSON を分けた数。分けた文書は `{表名}:{id}#{n}`）・`reset`（復元の印）。ほかに `users/{uid}/meta/app`（データの形の版。古い版のアプリは送るのを止めて「要更新」を出す）と `config/owner`（持ち主）。
- **送る**: 端末に保存するたびに、同じ書き込みの中で送信待ち（`_outbox`。最後にクラウドと揃えた内容 `base` を控える）に積む。変更から2秒後（続けて編集しても最大10秒）か、画面を閉じる・裏に回る時に送る。クラウドの指紋が `base` と同じ時だけ書く（トランザクション）。
- **受け取る**: 「前回受け取った時刻以降」をリアルタイムで購読し、送信待ちが無ければそのまま、あれば3者マージ（`base`・この端末・クラウド）して反映する。20分以上裏にあった後とオフラインから戻った時は購読し直す。
- **タブ**: 同期するのは1つのタブだけ（Web Locks）。状態はほかのタブに BroadcastChannel で知らせる（名前は `diary-studio-sync`）。
- **競合**: 短い項目は項目ごとに合わせ、両方で変えたらこの端末を優先する。長い文章（予定のメモ・やりたいことの本文・MIM の本文）は両方で書き換えていたら「――――（同期の競合: iPhone で同時に書かれた内容）――――」でつないで両方残す。片方で削除・片方で編集なら削除を優先し、編集した内容をゴミ箱に「同期の競合で残した内容」として残す（D10）。表ごとの指定は 6.10。
- **休みの日・ラベルの呼び名も同期する**（D10）。外観などの端末ごとの設定は同期しない（D16。6.13）。
- **月の束**: 何年分も溜まっても新しい端末の最初の受け取りが無料枠に収まるよう、古い月の項目をクラウドで月ごとの1文書にまとめる（D9。6.11）。NS には無い、新しく作る部分。

### 2.5 ログイン

- **最初にログインの画面を出し、ログインしてから使う**（Q27）。ログインしていない間は、トップ画面もデータも出さない。
- 流れ:
  1. 起動アニメーション（5.）の後、ログインしていなければ `#/login`（ログインの画面）。ログインの画面を描けたらアニメーションに「準備ができた」と知らせる。
  2. ［Google でログイン］。PC はポップアップ、ホーム画面に追加した iPhone（`navigator.standalone`）とポップアップが塞がれた時はページを切り替える方式（リダイレクト）。`web.app` で開いている時は、ログインの画面も同じドメインで開く（NS の `firebase.ts`）。
  3. 持ち主を確かめる: `config/owner` が無ければ、このアカウントを持ち主として記録する。あってほかのアカウントなら「このアカウントは Diary Studio の持ち主ではありません」と出し、［ログアウト］だけを出す（データは何も見えない）。
  4. この端末で前に別のアカウントを使っていた時は、同期を始める前に確かめる（NS と同じ）。
  5. トップ画面を出し、最初の受け取りが終わるまでヘッダーの同期の表示を「受け取り中…」にする。
- 一度ログインした端末は、次からはログインの画面を出さずにトップ画面を開く（電波が無くても開ける。ログインの状態は Firebase が端末に覚える）。
- 初めて開いた時に電波が無ければ、ログインの画面に「ネットにつながっていません。最初の1回はネットにつないでログインしてください。」と出す。
- **ログアウト**（設定 → 同期）: ログインの画面に戻る。端末の中のデータは消さない（同じアカウントで入り直せば続きから）。
- **ログインの画面の見た目**（参考画像の表紙・4.4）: 画面いっぱいに `--cover`（くすんだ青）の地。左寄せで、等幅の「Diary Studio」（Roboto Mono 300・40px。S は 32px）、その下に等幅の小さな字で今日の曜日と日付「TUE · 2026.11.10」（12px・字間 0.08em。表紙の「MONDAY START」の書き方は写さない）、さらに下に［Google でログイン］（地 `--surface`・字 `--text`・枠 1px `--border-strong`。ホワイトでは白い地、ダーク・ディープダークでは暗い面の色になり、暗い表紙の上でボタンだけがギラつかない。高さ 44px）。画面の左下に「DIARY STUDIO  v0.1」（10px）。ボタンの外の字は `--on-cover`（開発）。

### 2.8 アプリの更新・オフライン・無料枠

- **更新**: 新しい版を受け取ったら、画面の上に「新しい版があります ［更新する］」の帯を出す。押すと入力中の下書きを保存してから読み込み直す。勝手には読み込み直さない（D1）。
- **オフライン**: アプリの本体は事前にキャッシュし、電波が無くても開ける。電波が無い間の変更は端末に保存し、つながったら送る。
- **無料枠**（Spark）: Firestore は1日に読み取り5万回・書き込み2万回・削除2万回・保存 1GiB。個人の予定帳なら収まる（調査）。超えた日は同期だけ止まり、ヘッダーに「今日の無料枠を使い切りました（{戻る時刻} ごろに戻ります）」と出す。端末への保存は続く。
  - 無料枠は米国太平洋時間（`America/Los_Angeles`）の 0時に戻る。戻る時刻は、端末で「次の太平洋時間の 0時」を端末の時刻に直して出す（日本では 17:00、米国の夏時間の間（3月〜11月の初め）は 16:00。例「16:00 ごろに戻ります」）（調査）。

## 4. 外観とデザイン

### 4.1 方向

- ミニマルでスタイリッシュ、ギラつかないパステル（要件）。**色はダークの外観を基準に作り**、ホワイトはそれを白地用に直した物（Q24）。
- 参考画像（CHRONOGRAPHY FY2026）の「灰色と細い線と等幅の数字だけで組んだ静かな紙面」を土台にし、DS では色を区分とラベルとごく控えめな青だけに使う（Q18・D16・D17）。
- ボタン・入力欄・ダイアログ・トースト・線のアイコン・各端末の標準の書体は NS に揃える。DS だけの物は、カレンダーの見た目・パステルの区分とラベルの色・くすんだ青・広めの余白・等幅の英数字（D17）。

### 4.2 外観の種類と切り替え

- 4つから選ぶ: 端末の設定に合わせる／ホワイト／ダーク／ディープダーク（D16・要件）。初めは「端末の設定に合わせる」（NS と同じ。開発）。
- **端末ごとの設定**（同期しない。D16）。`localStorage` の `diary-studio:prefs` の `appearance`（`system`・`white`・`dark`・`deep-dark`）。
- 仕組みは NS と同じ: `<html data-theme>` に `white`・`dark`・`deep-dark` を入れ、CSS 変数を上書きする。最初の描画の前に `launch.js` の `boot()` が決め、起動後は `PrefsEffect` が同じ規則で反映して端末のライト／ダークの変化にも付いていく。ブラウザの枠の色（`meta theme-color`）は ホワイト `#ffffff`・ダーク `#17181b`・ディープダーク `#0e0f11`（`uiStore.ts` と `launch.js` の2か所に同じ値）。
- **ダーク**: ホワイトの背景を黒にし、文字を黒地用にした物（Q24）。パステル（区分の土台の色・ラベルの24色）は、ダークの黒地で見て決めた値を基準にする（Q24）。黒地で浮かないよう、カードや予定の地（土台の色の `--work-soft`・`--private-soft`）は暗く沈めた色にし、明るいパステルはラベルの左の一辺・●・線のような細い所だけに使う（開発）。ホワイトのパステルは、その色合いを保ったまま、白地で見えるよう明るさを下げて濃くした物（4.5・4.6。→22 の X2）。
- **ディープダーク**: カードやリストで区分を見分ける地の色（土台の色）をなくし、最小限の色だけで成り立つ見た目（Q24）。ラベル・差し色もほぼ灰色（色味をごくわずかに残す）（要件・Q24）。区分は位置（いつも仕事が先）と線のアイコン（仕事＝かばん、プライベート＝家）で見分け、休みは「休」の字、完了は斜線と✓で見分ける（Q24 のおすすめ案の中身）。

### 4.3 色の2段構え（区分の土台の色＋ラベルの色）

- **土台の色**は区分で決まり、変えられない: 仕事＝青、プライベート＝ピンク。外観ごとに値を調整する（Q14・I3）。ディープダークでは両方とも同じ灰色（区分の色分けをなくす）（Q14）。
- **ラベルの色**は項目ごとに 24色から選ぶ（選ばなくてよい）。仕事とプライベートで同じ24色を使う（Q14・I3）。
- 出し方:

  | 場所 | 土台の色 | ラベルの色 |
  |---|---|---|
  | ウィークリーのカード | カードの地（`--work-soft`／`--private-soft`） | 左の一辺（幅 4px）。ラベルが無ければ一辺を付けない（I3） |
  | デイリーのタイムスケジュールの予定 | 地 | 左の一辺（4px）。無ければ付けない |
  | デイリーの時間指定なしのリスト | 行の背景にマーカーを引いたような帯（`--work-marker`／`--private-marker`）（Q14） | 行頭の●（直径 10px）。無ければ土台の色の●（`--work-line`／`--private-line`）（I3・要件） |
  | Task List の行 | 行の背景にマーカー（Q14） | 付けない（Task List はラベルを出さない。詳しくで選べる） |
  | 複数日の線と終点の● | — | 線と●の色。無ければ土台の色（`--work-line`／`--private-line`） |
  | マンスリーの数字 | 数字の色（`--work-text`／`--private-text`） | — |
  | イヤーの● | ●の色（`--work-line`／`--private-line`） | — |

- **マーカー**: 区分の色を持つリストの行（デイリーの時間指定なしのリスト・Task List）は、行の背景に区分の色（`--work-marker`／`--private-marker`）を蛍光ペンで引いたように敷く。件名の欄（デイリーは行頭の●の右、Task List の L は要件の欄、M・S は件名の行）の左の端から行の右の端まで、行の高さの下 6割ほどの帯にする（その部分を包む要素に `background: linear-gradient(transparent 40%, var(--work-marker) 40%)`）。締め切り日・依頼者の小さな字の下には敷かない（淡い字が読みにくくなるため）。帯の上に置く字は `--text`（件名）と `--text-muted`（印・期間）だけにする（どちらも帯の上で 4.5:1 以上）（開発）。完了・済みの行とディープダークでは敷かない（Q14。→22 の X2）。
- `--work-line`・`--private-line`（ラベルが無い時の線・●）は、「ラベルなし」とその色のラベルを見分けられるよう、24色のどれとも OKLab の色の差（ΔE）を 0.06 以上離す（開発）。
- 区分の色は、ラベルの色と見分けやすいよう、ラベルより淡く彩度の低い地として使う（地はラベルの色より必ず明るさの差を 0.1 以上とる。4.5 の値はそうしてある）（開発）。

1. **等幅の英数字**: 数字（日付・時刻・件数・大きな数字）、英語の見出し（Calendar・Task List など）、曜日・月の英字（SUN・NOV）は Roboto Mono（`--font-mono`）。日本語の文章は各端末の標準のゴシック（`--font-ui`）。数字は `font-variant-numeric: tabular-nums` で桁をそろえる。等幅にするのは、数字や英字だけで1かたまりになっている所（カレンダーの日付・曜日・月、時刻、件数、見出しの英語、Task List の締め切り日、残りの字数）だけ。日本語の文・ボタン・お知らせ・詳細の日付（「11月10日（火）」）の中の数字は ui の書体のままにし、`tabular-nums` だけ付ける（文の途中で書体が替わらないように）（開発）。
2. **大きく淡い数字**: 操作の列の左に、見ている期間の数字を大きく淡く（3.7）。
3. **細い罫線**: 線は 1px の `--rule`。日のマス・日の列のいちばん上の線だけ 2px の `--rule-strong`（イヤー・マンスリー・ウィークリー）。カレンダーには影を付けない。
4. **点線の丸のチェック**: 3つのリスト・ウィークリーのカード・タイムスケジュールの予定の完了は、点線の丸（4.11）。
5. **曜日の丸いラベル**: ウィークリー・デイリーの日の見出しは、丸いラベル（角丸 999px・地 `--surface-3`・左右 8px・上下 2px）の中に等幅の英字3文字の曜日。今日は 7.3 の印（地 `--today-bg`・字 `--on-primary`・`--today-ring` の輪）にする。休みの日は、`--off-fill` の地の上で埋もれないよう、丸いラベルの地を `--surface` にする（開発）。マンスリーの曜日の列は丸いラベルにせず字だけ（参考画像 2 に近い）。
6. **時間の縞**: タイムスケジュールは1時間ごとに `--surface` と `--stripe` を交互に敷く。12:00 の線は 1px の点線、0:00 の線は 2px（11.3）。
7. **くすんだ青**: 表紙の青（`#a3bbd3`）から作った `--accent`・`--primary` を、今日の印・主なボタン・選んでいる所・リンク・フォーカスの枠だけに使う（D16）。
8. **月の見出しの帯**: イヤーの各行の左端に `--surface-3` の帯と等幅の「NOV」「2026」（8.2）。
9. **英字の曜日と月**: 画面の中の曜日と月は英字3文字（SUN MON TUE WED THU FRI SAT、JAN〜DEC）。ボタン・説明の文・詳細の日付（「11月10日（火）」）は日本語（参考画像・D46）。

## 5. 起動アニメーションとアプリアイコン

### 5.1 仕組み（NS から流用）

NS の起動アニメーション「グリッチ」の仕組みをそのまま使い、絵・色・時間・名前だけを変える（D18・NS SPEC.md 2.・nsMap）。

- `src/launch/launch.js`（var と function だけの1つの関数。古い iPhone の Safari 16 でも動く）を、開発でもビルドでも `index.html` にそのまま埋め込む（`vite.config.ts` のプラグイン。名前は `diary-studio:inline-launch-script`。ビルドでは縮める。中身に `</script` を書かない）。
- 最初の描画の前に `boot()` が外観（`<html data-theme>` と枠の色）を決める（4.2）。
- 画面いっぱいの重なり `div#ds-launch` を `<html>` の直下に置き、地の色だけをすぐ出す（`aria-hidden`・z-index 最大・ノッチの分の余白）。描くのは HTML を読み終えた後で、ふだんは Worker（OffscreenCanvas）、使えなければページの中の canvas、canvas も使えなければ何も出さない。描く関数は Worker に文字列で渡すので、関数の外の物を使わない。
- 名前の置き換え: `window.NovelStudioLaunch` → `window.DiaryStudioLaunch`、`novel-studio:prefs`・`novel-studio:launch`・`novel-studio:launched` → `diary-studio:…`、`ns-launch` → `ds-launch`。
- 外観の項目名: NS の `resolveAppearance` は `prefs.theme` を読むが、DS の項目は `prefs.appearance`（4.2・6.13）。写したままだと、最初の描画の前の外観と起動アニメーションの色がいつも「端末の設定に合わせる」になるので、`resolveAppearance` が読む項目を `prefs.appearance` に変える（`uiStore.ts` の Prefs と `resolveAppearance` も `appearance` にする。NS 1.x の `'light'` を `'white'` に読み替える分岐は消す）。`launch.test.ts` の外観のテスト（`{ appearance: 'deep-dark' }` ならディープダーク、知らない値なら端末の設定に合わせる）も `appearance` で書く（開発）。
- 外す物: `isNativeApp`・`hideNativeSplash` と、`decide` のアプリ（native）の分岐（Web だけになる）。

### 5.2 出す時・消える時（NS と同じ）

- **出す時**: ウインドウ・タブを開いた最初の1回だけ（`sessionStorage` の `diary-studio:launched`。再読み込みでは出さない。新しいタブ・インストールしたアプリの新しいウインドウでは出す）。見えていないタブで開いた時は出さず、見えた時に出したことにする。設定 → 表示 の「起動アニメーション」（オン／オフ。初めはオン。端末ごと）がオフなら出さない。テスト（`navigator.webdriver`）では、`localStorage` の `diary-studio:launch` が `force` か、URL に `launch=1` がある時だけ出す（D18）。
- **消える時**: アニメーションが終わり、かつアプリが最初の画面を出せた（`appReady`）の両方がそろったら、0.25秒（`fadeMs`）で薄くなって消え、canvas と Worker を手放す。`appReady` は、ログインしていなければログインの画面を描いた後、ログインしていれば端末の中のデータを読み込んでトップ画面を描いた後に `main.tsx` が呼ぶ（`afterNextPaint`。止まっていても1秒で呼ぶ）。知らせが来なくても出してから 5秒（`capMs`）で消える。画面を押す・キーを押すとすぐ消え始める（押した所の下は押されない。指・マウスを離して 0.1秒たつまで重なりが操作を受け止める。押したままでも3秒で取り除く）。
- **視差効果を減らす**（`prefers-reduced-motion`）: 動かさず、最後の絵（ロゴ）を描いてから 0.5秒（`stillMs`）出して消える。

### 5.3 絵の流れ

### 5.5 日記の点の絵

点の升目で描く。`#` は明るい点（`logo` の色。光の付け方は NS の `logoRest` と同じ）、`+` は淡い点（`logo` を不透明度 0.28）、`.` は消えている点（`logo` を不透明度 0.06）。点は NS の `logoImage` と同じく、一辺 `qd = Math.max(1, Math.round(pd × 0.78))` の角丸の無い四角にし（ロゴの点と同じ形）、状態ごとに先に1枚の絵にしておく（NS）。

**閉じた日記帳**（17列×20行。0列が背、1〜16列が表紙。表紙は左の縁 1列・右の縁 16列・0行・19行が `#`、中は `+`。題の札は 4〜9列×4〜8行、留めのゴムは 12列）:

##++++++++++#+++#
##++++++++++#+++#
##++######++#+++#
##++#....#++#+++#
##++#....#++#+++#
##++#....#++#+++#
##++######++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#
##++++++++++#+++#

**見開き**（33列×20行。左のページ 0〜15列、背 16列、右のページ 17〜32列）: 外の枠（0行・19行・0列・32列）と背（16列）は `#`、ページの中は `.`。右のページの3行目の 18・20・22・24・26・28・30列が曜日の点（`T_GRID` までは `.`）、6・8・10・12・14行目の同じ列が週の点（初めは `+`）。`T_GRID` で曜日の行、続いて週の行が上から灯り、灯った点は灯ってから 0.06秒だけ `hot` の色で、その後は `#`（`logo` の色）のまま残す。

**表紙が開く8コマ**（`T_OPEN0`〜`T_SPREAD`。0.03秒ずつ）（開発）: 閉じた日記帳は見開きの 16〜32列にぴったり重ねる（日記帳の 0列＝見開きの背の 16列、日記帳の 16列＝見開きの 32列）。背（16列）はどのコマでも `#` のまま動かさない（ここが回る軸）。

- コマ1〜4: 表紙の幅 w を 16→11→6→2 列にする。表紙は見開きの 17〜(16+w) 列に描く（外の縁は `#`・中は `+`。題の札とゴムは w=16 の時だけ）。表紙に隠れていない右のページ（(17+w)〜32列）は、見開きの右のページ（外枠 `#`・中 `.`・曜日と週の点）をそのまま出す。
- コマ5〜8: 表紙の裏（＝左のページ）が背から左へ w = 2→6→11→16 列で開く（(16−w)〜15列。外の縁は `#`・中は `.`）。右のページは全部見える。コマ8 で見開き（`T_SPREAD`）になる。

- 大きさ: 点の間隔は NS のロゴと同じ書き方で、`pd = Math.max(2, Math.round(Math.min(安全な幅 × A ÷ 33, 安全な高さ × 0.5 ÷ 20) × dpr))`（実ピクセルの整数）、`p = pd ÷ dpr`（CSS ピクセル）。A は横長の画面で 0.62、縦長の画面（安全な幅 < 安全な高さ）で 0.88（iPhone 14 の縦では p ≈ 10.3px、見開きの幅 341px）（開発）。閉じた日記帳も見開きと同じ間隔で描く。全体を、ノッチ・ホームバーを除いた所の中央に置く（NS）。

### 6.3 カレンダーに出る条件と期間（Task List の4通り）

- **カレンダーに出るか**: `origin === 'calendar'` か、`due` がある時（Q2・I7）。ゴミ箱の物は出さない。
- **期間**（`from`〜`to`。どちらも含む）:
  - calendar 生まれ: `from = start`、`to = due ?? start`（I7。締め切り日が空ならその日1日）。
  - list 生まれ（`due` がある時だけ）: `from = (start があり start ≤ due) ? start : due`、`to = due`（Q2）。
- **複数日の予定**: `from < to` の物。
- **Task List の4通り**（list 生まれ。Q2・I7）:

  | | 開始日 | 締め切り日 | Task List | カレンダー |
  |---|---|---|---|---|
  | ① | なし | なし | 出る | 出ない |
  | ② | なし | あり | 出る | 締め切り日の1日の予定。カード・行に「〆」 |
  | ③ | あり | あり | 出る | 開始日〜締め切り日の予定。「〆」 |
  | ④ | あり | なし | 出る | 出ない（I7） |

- **「〆」の印**: list 生まれでカレンダーに出ている物に付ける（Q2）。等幅の欄の右に 11px の「〆」。
- **カレンダーで入れた予定**: 開始日が必須、締め切り日は任意（I7）。
- **Task List に出るか**: `listed` が true で、ゴミ箱に無く、「済んでから 7日を過ぎた物」（`done` で `doneAt` が今から 7日（168時間）より前）でない物（Q22 のおすすめ案の中身）。7日を過ぎて見えなくなっても、データ・カレンダー・Task View には残る。
- **移り変わり**:
  - list 生まれの締め切り日を消すと、カレンダーから消えて Task List にだけ残る（Q2）。その時 `listed` が false なら true に戻し、「カレンダーから外れたので Task List に戻しました」と出す（どこにも出ない項目を作らないため）（開発）。
  - 「Task List から外す」（`listed = false`）は、カレンダーに出ている時だけ選べる（Q6 のおすすめ案の中身・開発）。
  - calendar 生まれの予定は、詳細の「Task List にも出す」をオンにすると Task List にも出る（D38）。開始日は必須なので、どこにも出ない状態にはならない。
- **入力の決まり**（D33・I7）:
  - 開始日を締め切り日より後にしたら、締め切り日を開始日と同じ日にそろえる（1日の予定になる）。締め切り日を開始日より前にしようとした時も、開始日を締め切り日にそろえる（D33・開発）。
  - list 生まれで開始日だけを締め切り日より後にした時も同じ（そろえる）。
  - 日付を選ぶ小窓では、締め切り日の小窓で開始日より前の日も押せ、押すと開始日もその日にそろえる（1日の予定になる）。開始日の小窓で締め切り日より後の日を押すと、締め切り日もその日にそろえる（開発）。
  - 終了時刻が開始時刻と同じ時（10:00〜10:00）は、終了時刻を空にする（開始時刻だけの予定になる）（開発）。
  - そろえた結果、1日の予定で終了時刻が開始時刻より前になる時は、その日付にはできない（6.4）。

### 6.4 日付と時刻の持ち方

- 日付は端末の暦の `'YYYY-MM-DD'`、時刻は `'HH:MM'`（24時間）の文字で持つ（D4）。日付と時刻は壁時計の値で、時差では動かさない（日本で入れた 11/10 10:00 の予定は、端末の時刻を海外にしても 11/10 10:00 に出る。予定の日がずれない）（D4・開発）。
- 日時（作った・直した・完了した・取り込んだ）は `Date.now()` のミリ秒（UTC）の数で持つ（NS と同じ。6.1）。暦の日付の文字で持つのは `start`・`due`・`doneOn`・`offDays` の id と `date`・`routineChecks.dates`（月は `routineChecks.month`）だけ（開発）。
- **今日**は端末の時計の暦の日付。ルーチンのチェックの日・`doneOn` も、その時の端末の暦の日付（D4）。日の変わり目は端末の 0時（D4・D35）。次の 0時にタイマーで「今日」を計算し直し、画面が見えるようになった時（`visibilitychange`）・フォーカスが戻った時にも計算し直す（ルーチンの戻り・今日の印・締め切りを過ぎた色が変わる）。
- 日付が変わっても、見ている期間は動かさない（今日の印だけを移す）。ただし、アプリが裏から戻った時に、最後の操作から 6時間以上たっていて、見ている期間が前の「今日」を含んでいれば、新しい今日を含む期間へ移す（Q20 の「開いた時」と同じ扱い）（開発）。
- 週は日曜〜土曜（要件）。年は1月〜12月、四半期は1・4・7・10月の1日から（D35）。
- **時刻のある予定**（Q13）:
  - 1日の予定: その日の `startTime`〜`endTime`。`endTime` が無ければ開始時刻だけの予定（タイムスケジュールでは `min(開始 + 30分, 24:00)` までの枠。D28）。
  - 終了時刻は `'24:00'` も持てる（終了の一覧の最後に 24:00 を置く。開始時刻には使えない）。1日の予定の 22:00〜24:00 はその日だけの予定。終了に 00:00 を打った・選んだ時は 24:00 と読む（翌日にしない）（開発）。
  - 複数日の予定: `from` の `startTime` に始まり、`to` の `endTime` に終わるひと続き（Q13）。間の日は 0:00〜24:00 のすべて。`endTime` が無ければ最終日は 24:00 まで。`startTime` が無く `endTime` だけは持てない。最終日の終了が 00:00 になった時は、締め切り日を1日前にして終了を 24:00 として保存する（開発）。
  - 1日の予定で `endTime` が `startTime` より前（例 22:00〜02:00。終了が 00:01 以後で開始より前の時）なら、締め切り日を翌日にして2日にまたがる予定として保存する（list 生まれは開始日を元の締め切り日、締め切り日を翌日にする）。入力欄の下に「翌日 02:00 まで」と出してから保存する（D33 の「終了が開始より前なら翌日までと読む」を形にした物）。
  - この「翌日にする」は、時刻を入れた・直した時（登録の画面・詳細の時刻の欄）だけに当てる。日付を動かした時（ドラッグ・詳細の日付の欄・Task List の日付のメニュー）に「1日の予定で終了 < 開始」になる時は、その日付には動かせない。ドラッグでは落とせる日にしない（7.11）。詳細などでは日付の欄の下に「終わりの時刻が始まりより早いので、この日付にはできません（先に時刻を直してください）」と出し、元の値に戻す（開発）。
  - 時刻は 5分刻みで選べ、打てば1分単位も入る（D33）。

### 6.5 休み（`offDays`）

- 1日 = 1記録。`id` は日付（`'2026-11-10'`）、項目は `date`・`off`（boolean）と 6.1 の共通の項目（`updatedAt`・`by`・`ai`・`via`）。
- 付ける・外すは `off` を切り替える（記録は消さない。同期で消した・付けたが食い違わないように）（開発）。
- すべて手で付ける。土日祝を自動では付けない（Q9）。ゴミ箱には入れない。

### 6.6 ラベルの呼び名（`labelNames`）

- 1色 = 1記録。`id` はラベルのキー（`'sky-l'` など）、項目は `name`（0〜12字。空は名前なし）と 6.1 の共通の項目。全端末で同じになる（Q14・D5・I3）。
- 付けた名前は、後で作るコネクタからも色を名前で指すのに使う（Q14）。

`src/sync/merge.ts` の指定を DS の表で書く（D10）。書いていない項目は「項目ごとに合わせ、両方で変えたらこの端末」。

| 表 | 長い文章（両方残してつなぐ。`TEXT_FIELDS`） | 並び（`LIST_FIELDS`） | 削除と編集が重なったら編集をゴミ箱に控える（`TEXT_TABLES`） |
|---|---|---|---|
| `items` | `memo` | — | ○ |
| `offDays` | — | — | — |
| `labelNames` | — | — | — |
| `routines` | — | `weekdays`（値で） | ○ |
| `routineChecks` | — | `dates`（値で） | — |
| `favorites` | `text` | — | ○ |
| `mimNotes` | `body` | `secrets`・`qrs`（`id` で） | ○ |
| `inbox` | — | — | — |
| `trashEntries` | — | `recordIds`（NS） | — |

### 6.11 月の束（古い月の項目をまとめる）

何年分も溜まっても、新しい端末で初めて全部を受け取る時の読み取りが1日の無料枠（5万回）に収まるようにする（D9・調査）。端末の中の持ち方は変えず、クラウドの置き方だけを変える。NS には無い、新しく作る部分（`src/sync/packs.ts`）。

- **対象**: `items` だけ（`routineChecks` は初めから月ごと、ほかは数が少ない）。
- **束の文書**: `users/{uid}/records/itemPack:{YYYY-MM}`。`json` は `{ month, items: { [id]: 項目 } }`。大きければ NS の分割（`chunks`）で分ける。アクセスルールは記録と同じ。
- **項目の月**: カレンダーに出ている物は `to` の月、出ていない物は `doneOn`（無ければ `createdAt` の暦の日付）の月。
- **まとめる条件**: 項目の月が今月の3か月前より前（今が 2026年11月なら 2026年7月まで）、最後に直してから 60日以上、送信待ちが無い、まだ束に入っていない。
- **まとめる時**: 同期を受け持つタブが1日に1回（その日の最初の同期が終わってから、操作の無い 30秒の後）。1回に最大 450件。月ごとに1つのトランザクションで、束の文書（指紋を確かめる）に項目を足して書き、各項目の文書を本当に消す（削除の印は書かない）。この端末の `_meta` に「項目 id → 入っている束の月」を覚える。
- **受け取る時**: 束の文書が届いたら、中の項目を1件ずつふつうの記録として受け取る（3者マージも同じ）。束から項目が抜けた時は何もしない（同じトランザクションで個別の文書として届く）。
- **束の中の項目を直した・消した時**: 送る時に、1つのトランザクションで束からその項目を抜いて書き直し、個別の文書（消した時は削除の印）を書く（束から出す）。
- **削除の印の片付け**: 同じ1日1回の処理で、90日より前の削除の印の文書を本当に消す。ただし、内容から作った id の記録（id が `ce-`・`ct-`・`cf-` で始まる、AI から取り込んだ物）の削除の印は片付けない（数が少なく、片付けると、消した物と同じ内容が届いた時にまた取り込まれるため。19.4）（開発）。
- **90日を超えて同期していなかった端末**: 次の同期で全部を受け取り直し、クラウドにも送信待ちにも無い端末の中の記録を消す（ほかの端末で消され、印も片付いた物）。「しばらく同期していなかったので、全部を受け取り直しました」と出す。

### 6.12 修復（表示用）

起動時・バックアップの読み込み時・同期で記録を受け取った時（3者マージの後を含む）に、表示用の内容だけを直す。直した値はすぐにはクラウドに書き戻さず、次にその記録を保存する時に書く（NS の `repair` の考え方）（NS・開発）。

- `items`: 日付・時刻の形が正しくない値は null とみなす。calendar 生まれで `start` が無い → `due`、それも無ければ `createdAt` の暦の日付。`start > due` → calendar 生まれは `due = start`、list 生まれは `start` を無いものとみなす（締め切り日は動かさない。6.3 と同じ）。`startTime` が無いのに `endTime` がある → `endTime` を無視。1日の予定で `endTime ≤ startTime` → `endTime` を無視。list 生まれで `due` が無く `listed` が false → `listed = true` とみなす（どこにも出ない項目を作らない。6.3。お知らせは出さない）。知らない `kind` → `'work'`。知らない `label` → なし。`title` が空 → 「（件名なし）」。
- `routines`: 知らない `cycle` → `'daily'`。範囲の外の `weekdays`・`monthDay`・`yearMonth`・`yearDay` → 指定なし。`cycle` に合わない指定（毎週以外の `weekdays` など）は無視する。`yearMonth` と `yearDay` の片方だけがある時は指定なしとする。
- `routineChecks`: 親の無い記録は見えなくする。
- 知らない項目は消さずに残す（新しい版のアプリが足した項目を壊さない）。

### 6.14 受け取り箱（`inbox`）

AI（後で作るコネクタ）からの書き込みを受ける入口（I6。19.）。コネクタは新しく作ることだけができ、アプリが同期の時に本物の記録に取り込む。

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | コネクタが作るランダムな id（`x-{uuid}`）。同じ内容が2回届いても文書がぶつからないよう、内容からは作らない（二重の登録は、取り込む時に「作る記録の id」で防ぐ。19.4） |
| `by` | `'connector'` | いつも `'connector'`。アクセスルールでもこの値だけを許す（I6） |
| `target` | `'item'` \| `'task'` \| `'favorite'` \| `'trash'` | 何として取り込むか（予定・タスク・やりたいこと）。`'trash'` は AI が足した記録をゴミ箱へ移す依頼（19.4・D48） |
| `payload` | object | 中身（19.3 の形） |

| `createdAt` | number | コネクタが作った日時（ミリ秒） |

| `status` | `'new'` \| `'added'` \| `'trashed'` \| `'duplicate'` \| `'previously_deleted'` \| `'invalid'` | コネクタは `'new'` でだけ作れる。アプリが取り込んで書き換える（`'trashed'` はゴミ箱へ移す依頼を済ませた物） |

| `message` | string \| null | `invalid` の理由（日本語） |
| `processedAt` | number \| null | 取り込んだ日時 |

- コネクタが作れるのは、`status: 'new'`・`by: 'connector'` で、`resultId`・`message`・`processedAt` が null の記録だけ（アクセスルール。19.5）。
- 取り込んで 30日たった記録は、アプリが消す（削除の印。6.11 で片付く）。

### 6.15 ゴミ箱

NS の `trashEntries`・`trashRecords` と同じ形で、30日とっておき、元の場所へ戻す（D13）。1時間ごとに期限切れの物を完全に削除する（NS の `TrashPurge`）。

| 種類（表示） | 中身 | 場所（表示） |
|---|---|---|
| 予定 | カレンダーに出ていた項目 | 「カレンダー 11/10（火） 仕事」 |
| タスク | カレンダーに出ていなかった項目 | 「Task List」 |
| やりたいこと | 1件 | 「Favorite List」 |
| 済みのやりたいこと | 「済みを片付ける」でまとめた n件（戻すとまとめて戻る） | 「Favorite List」 |
| ルーチン | ルーチンとそのチェックの記録 | 「Routine List › 毎週」 |
| MIM のメモ | 1枚 | 「MIM」 |
| 同期の競合で残した内容 | NS と同じ | 元の場所 |

- 戻すと、同じ1件が Task List とカレンダーの両方に戻る（Q6 のおすすめ案の中身）。ルーチンはチェックの記録ごと戻る。
- 内容から作った id の記録（AI から取り込んだ物）は、同じ id がもうあれば戻さない（NS）。

### 6.16 バックアップの形

- JSON の1ファイル: `{ format: 'diary-studio-backup', version: 1, exportedAt, appVersion, includesMim, tables: { items, offDays, labelNames, routines, routineChecks, favorites, mimNotes?, inbox, trashEntries, trashRecords } }`。ファイル名は `diary-studio-backup-2026-11-10.json`（D15）。

## 7. カレンダー共通

### 7.1 週・曜日・土日の色

- 週は日曜始まり（要件）。曜日は英字3文字（SUN MON TUE WED THU FRI SAT）の等幅（4.4）。読み上げは日本語（「日曜日」）。
- 土曜の日付・曜日は `--sat`、日曜・祝日は `--sun`（D16）。休みは色ではなく地の色と「休」の字（7.4）。

### 7.2 祝日

- `@holiday-jp/holiday_jp` で判定する（振替休日・国民の休日を含む。1970〜2050年）。外部のカレンダーとはつながない（D11・D12）。
- 年ごとに1回 `between(1月1日, 12月31日)` で日付 → 祝日名の表を作って覚える（`src/domain/holidays.ts`）。2051年以降は「祝日なし」とする。
- 祝日名を出す所: マンスリー（L・M）のマスの右上、ウィークリー・デイリーの日付の見出しの下。S のマンスリーとイヤーは日付の色だけ（D12）。
- 毎年2月ごろ（翌年の春分・秋分の日が発表された後）に部品を新しくして公開し直す（D12）。

### 7.3 今日

- 今日の印は、どの外観でも、地 `--today-bg`・字 `--on-primary` に加えて、1.5px の輪（`box-shadow: 0 0 0 1.5px var(--today-ring)`）と日付の字の太さ 600 で示す（ディープダークでは地の色の差が小さいので、輪と太さで分かるようにする。4.12）（開発）。
  - マンスリー: 日付を直径 22px の丸に入れる。ウィークリー・デイリー: 曜日の丸いラベル。イヤー: マスの内側に 2px の `--accent` の枠（輪の代わり）。デイリーのタイムスケジュールに今の時刻の線（11.3）。
- 3.3 の［MIM］と 9.5 の［休み］の押した状態、8.2 の今月の帯も、地を `--today-bg` にして同じ輪を付ける（開発）。
- 日付が変わったら（6.4）すぐに印を移す。

### 7.4 休み

- **シフトの休みを手で付ける**（Q8・Q9）。土日・祝日は自動で休みにしない。
- 付ける所: マンスリーの［休み］で休みを付ける状態にして日付を押す（Q19。9.5）、ウィークリーの日付の見出しの横の小さなチェック（Q19 のおすすめ案の中身。10.2）。イヤー・デイリーでは付けられない（見えるだけ）。
- 見え方: その日のマス・列・行の地を `--off-fill` にし、「休」の字（10px・`--off-text`）を日付の横に出す（Q19 のおすすめ案の中身）。祝日の赤い日付とは別の印（祝日で休みの日は両方が出る）。曜日の丸いラベルの地は `--surface` にする（4.4）。ディープダークでは、休みの地の上の淡い字を `--text-muted` で出す（4.5）。
- 休みでも、その日の予定は数えて出す（Q8）。

### 7.5 同じ日の中の並び

ウィークリーのカード・デイリーのリストで、同じ日・同じ段の中は次の順（D26 を Q12 に合わせて直した物）:

1. 複数日の予定（ウィークリーは 7.8 のレーンの順。デイリーのリストは開始日の早い順 → 締め切り日の遅い順 → 作った順）
2. 時刻のある1日の予定（開始時刻 → 終了時刻の順）
3. 時刻の無い1日の予定（作った順。`order` の小さい順）
4. 完了した予定（1〜3 と同じ決まりで）

- 完了した複数日の予定は、ウィークリーではレーンの位置に残す（線をつなぐため）。デイリーのリストでは4番目（完了した物）の先頭へ移す（開発）。
- 手での並べ替えは作らない（D26）。

### 7.6 件数の数え方

マンスリーのマスの数字（要件・Q8）:

- その日 d・区分 k の数 = 「カレンダーに出ていて（6.3）、完了していない、区分が k の、期間 `from ≤ d ≤ to` の項目」の数。ゴミ箱の物は数えない。
- 複数日の予定は期間中の毎日に数える。休みの日にも数える（Q8）。
- 完了すると、その予定の期間中のすべての日から −1 になる（要件）。
- ルーチンは数えない（D41）。
- 100 以上は「99+」と出す（開発）。

### 7.7 予定の中身の出し方（共通）

- **時刻の表記**（等幅 11px）:

  | 予定 | 表記 |
  |---|---|
  | 1日・時刻なし | 出さない |
  | 1日・開始だけ | `10:00` |
  | 1日・開始〜終了 | `10:00–11:30` |
  | 複数日・時刻なし | `〜11/11`（最終日には `11/9〜`） |
  | 複数日・時刻あり | `11/9 10:00〜11/11 15:00` |

- **印**（右上に小さく。並びは左から）: 「〆」（list 生まれ。6.3）、`LockIcon`（ロック中。12px。4.10）、AI の札（`by` が `connector` の物。枠だけの小さな札に「Claude」など。10px。押すと出どころのメモ `via` を出す）（I6・D48）。
- 依頼者とメモはカードには出さず、詳細で見る（D26）。

### 7.8 複数日の予定の見せ方（線と●）

帯にはしない。開始日にカード、締め切り日に終点の「●」を置き、その間を細い線でつなぐ（Q12）。

- **始点のカード**: 開始日の所に、1日の予定のカードと同じ見た目（土台の色の地・ラベルの一辺）で出す。件名は1行、下の行に期間（7.7）。左上に点線の丸（16px。4.11）を置き、押すと予定全体を完了にする（Q3・D29）。
- **線**: カードの端から●の中心まで、太さ 2px。色はラベルの色、ラベルが無ければ土台の色（`--work-line`／`--private-line`）。完了したら `--done-text`。
- **終点の●**: 直径 10px の丸。色は線と同じ。押せる所は 28px 四方（押すと詳細、長押し・ドラッグで締め切り日を動かす。7.11）。
- **受けた表示**: 前の週（前の日）から続いている時、見えているいちばん初めの日に出す「開始日のカードを受けた表示」。カードと同じ大きさで、地は透き通らせ、1px の点線の枠（線と同じ色）、中は「‹ 件名」（12px・`--text-muted`・1行）。完了の丸は置かない。押すと詳細（Q12）。
- **端の矢印**: 次の週（次の日）へ続いている時、線を見えている最後の日の端まで延ばし、端に「＞」（等幅 12px・線と同じ色）を出す（Q12）。
- **週の端の日**: 始点が週の最後の日（土曜）にあり次の週へ続く時は、カードの幅を 14px 縮め、あいた所に＞を出す（線は引かない）。終点が週の最初の日（日曜）にあり前の週から続く時は、受けた表示の右端の中に●を置く（線は引かない）（開発）。S の縦の並びは 10.4。
- **月をまたぐ時**: Q12 の答えの「週・月をまたぐ時」は、ウィークリーの週の境で切れる時と読む。週の中で月が変わっても線は切らない（11/29〜12/5 の週の 11/30 から 12/1 へは、そのまま線が続く）。マンスリーは要件どおり数字だけで、線と●は出さない（→22 の I1）。
- **レーンの割り付け**（ウィークリー。`src/domain/tracks.ts`）: その週・その区分の複数日の予定を、週の中に切り詰めた期間（`max(from, 日曜)`〜`min(to, 土曜)`）で、始まりの早い順 → 終わりの遅い順 → 作った順に並べ、前から順に「そのレーンの最後の予定の終わり < この予定の始まり」となる、いちばん上のレーンに入れる。1つのレーンの高さは 40px（カード 36px＋すき間 4px）。1日の予定は、すべてのレーンの下に並べる。
- 時刻のある複数日の予定も、ウィークリーでは同じ線と●で出す（時刻は期間の表記に出す）。デイリーでの出し方は 11.2・11.3。

### 7.10 ロックの見え方

- ロックは、ウィークリーでドラッグできなくするだけ。詳細ではいつでも直せる（要件・D30）。
- カード・タイムスケジュールの予定・デイリーのリストの行の右上に `LockIcon`（12px・`--text-muted`。4.10）。
- ロック中のカード・始点・●を掴もうとすると、持ち上がらずに 240ms 揺れる（左右 3px を3回）。知らせの文は出さない（Q11 のおすすめ案の中身）。視差効果を減らす時は揺らさず、`LockIcon` を 600ms だけ `--accent` の色にする（4.9）。PC ではマウスのカーソルを `not-allowed` にする。

### 7.11 ドラッグ＆ドロップの決まり

`@dnd-kit/react`（版を固定）で作る（D11）。

- **できる所**: ウィークリーのカード・複数日の始点のカード・終点の●（I1・Q12）。ほかに、L の Task List の行 → カレンダー（13.6）、リストの並べ替え（Routine・Favorite・MIM のメモ）。
- **掴み方**（Q11・I1）:
  - マウス: 押したまま 5px 動かすと掴む。
  - 指: 0.4秒押し続けると（その間 8px 以内）掴んで浮く。すぐに指を動かした時はふつうのスクロール。軽く押して離すと詳細が開く。
  - 掴むと 1.03倍・`--shadow-lift` で浮く。Android は 15ms 振動する（`navigator.vibrate`。iPhone のブラウザは振動しないので見た目だけ）（Q11）。
  - 文字の選択と iPhone の長押しのメニューは CSS で止める（`user-select: none`・`-webkit-touch-callout: none`。NS と同じ）。カードには長押しのメニューを付けない（ぶつかるため）。
- **落とせる所**: 同じ週の、同じ区分の段の日（Q1・D27）。仕事↔プライベートはまたげない（要件・I1）。落とせる日は地を `--accent-soft` にし、さらに 1px の `--accent` の点線の枠を付ける（地の色だけでは、ディープダークでほとんど変わらないため。開発）。落とせない所は変えない。画面の端に近づくと自動でスクロールする（dnd-kit の標準）。
- **動かすと変わる物**:

  | 掴んだ物 | 落とせる日 D | 変わる物 |
  |---|---|---|
  | 1日の予定（calendar 生まれ） | 同じ週・同じ段のどの日でも | `start = D`（`due` があれば `due = D` も） |
  | 1日の予定（list 生まれ・〆） | 同じ | `due = D`（`start` があれば `start = D` も）（Q2 のおすすめ案の中身） |
  | 複数日の始点のカード | 同じ区分の段で D ≤ 締め切り日 | `start = D` だけ（期間の長さが変わる。同じ日まで置ける。同じ日に置くと1日の予定になる）（I1） |
  | 複数日の終点の● | 同じ区分の段で D ≥ 開始日 | `due = D` だけ（I1） |

  - 時刻は変えない（日だけ変わる）（D27）。カード同士の日付の交換はしない（D27）。
  - 完了した予定も動かせる（開発）。
- **動かせない時**: ロック中（7.10）、週の外（週の外へは詳細で日付を変える。D27）、開始日を締め切り日より後・締め切り日を開始日より前（I1）、動かすと「1日の予定で終了時刻 < 開始時刻」になる日（例: 11/10 23:00〜11/11 01:00 の始点を 11/11 へ。その日は落とせる日にしない。6.4）。
- 受けた表示と端の矢印は掴めない（押すと詳細を開くだけ。長押ししても浮かず、揺れもしない）。始点がその週に見えていない予定の開始日と、終点が見えていない予定の締め切り日は、その週では動かせない（始点・終点が見えている週で動かすか、詳細で直す）（開発）。
- **期間をまるごと動かす**操作は無い（始点と終点を順に動かすか、詳細で直す）（I1。→22 の I1）。
- **動かした後**: 画面の下に 6秒「11/12（木）へ移しました［元に戻す］」（Q11 のおすすめ案の中身・D14）。始点は「開始日を 11/10（火）にしました」、終点と list 生まれは「締め切り日を 11/14（土）にしました」。［元に戻す］で動かす前の日付に戻す。移った先のカードを 1.2秒目立たせる（4.9）。
- 指で操作できない人のために、どの動きも詳細の日付の欄で同じことができる。

## 8. イヤー

年間のカレンダーで、予定のある日に印を付けるだけの画面。ここでは何も直せない（要件）。操作の列には［Task View］を出す（要件）。［休み］［＋ 登録］は出さない。

### 8.1 並べ方の選び方

- カレンダーの領域の幅が 870px 以上の時は「月を行・日を列」（8.2。参考画像 3）、それより狭い時は「小さな月を並べる」（8.3）（開発）。1日のマスの幅が 24px を切ると日付が読めないため（8.2 の式で 64 + 31 × 24 + 31 × 2 ＝ 870px）。

### 8.2 月を行・日を列（広い時）

- 12行（1月〜12月）×31列（1〜31日）。各行の左に月の見出しの帯（幅 64px・地 `--surface-3`・等幅の「NOV」13px・500 と「2026」10px を真ん中に。今月の帯は地 `--today-bg`・字 `--on-primary`・`--today-ring` の輪。7.3）（参考画像 3）。
- 日のマス: 幅は（領域の幅 − 64px − すき間）÷ 31、高さ 52px、マスの間のすき間 2px。上の線 2px の `--rule-strong`（参考画像 3）。中は左上に等幅の日付（12px）、その下に英字3文字の曜日（9px・500。日付と曜日の色は 7.1）、右上に●（下の決まり）。
- その月に無い日（2月30日など）は何も描かない（線も無し）。
- ●（要件・D25）: マスの右上に、直径 5px の●を置く場所を2つ決めておく（左＝仕事・右＝プライベート。間 2px）。仕事の予定がある日は左の場所に `--work-line`、プライベートは右の場所に `--private-line` の●を出し、片方だけの日も場所は動かさない（ディープダークでは2色が同じ灰色になるので、場所で見分ける。Q14・Q24 のおすすめ案の中身）。
  - 「予定がある日」は、その日がカレンダーに出ている項目の期間（`from ≤ d ≤ to`。6.3）に入っている日。複数日の予定は期間中の毎日（7.6 の数え方と同じ日）。完了した物も入れる。例: 11/28〜12/2 の仕事の予定なら、11/28・11/29・11/30・12/1・12/2 に仕事の●が付く（開発）。
  - その日のその区分の予定が全部完了なら、その●を不透明度 0.35（7.9）。
- 休みの日はマスの地を `--off-fill`、日曜・祝日の日付と曜日は `--sun`、土曜は `--sat`。祝日名は出さない（D12）。今日は 7.3。
- 縦に収まらなければ、カレンダーの領域の中でスクロールする。

### 8.3 小さな月を並べる（狭い時）

- 小さな月（月の名前「NOV」13px・500（今月は `--accent`）、曜日の頭文字の行 S M T W T F S（等幅 9px）、7列×6行のマス）を、列の数 = `floor(領域の幅 ÷ 170px)`（2〜4）で並べ、上から1月〜12月。S は2列。
- マスは 22px 四方以上。日付は真ん中に等幅 11px。●は右上の決まった2つの場所に直径 4px（8.2 と同じ決まり）。休み・土日・祝日・今日は 8.2 と同じ決まり。

### 8.4 押した時

- どの日のマスを押しても、その日の月のマンスリーへ移る（要件・D25）。月の見出しを押すとその月の1日を見ている日にして移る。PC はマスに乗せると地を `--surface-3` にする。

## 9. マンスリー

月の予定の量を数字だけで見る画面（要件）。操作の列に［休み］［＋ 登録］［Task View］を出す（要件）。

### 9.1 マス目

- 7列（SUN〜SAT）。行はその月に掛かる週の数（4〜6行）。いちばん上に曜日の行（等幅 11px・500・大文字。日曜は `--sun`、土曜は `--sat`。左寄せで左の余白 8px）。
- 各マス: 左に 1px の `--rule`（いちばん左の列を除く）、上に 2px の `--rule-strong`（参考画像 2）。中の余白は上下 6px・左右 8px。L・M のマスの高さは `max(88px, (領域の高さ − 曜日の行) ÷ 行の数)`。S は 56px 以上。

### 9.2 マスの中

- 左上: 日付（等幅 13px。S は 12px）。今日は 7.3 の丸。休みの日は日付の右に「休」（7.4）。
- 右上（L・M）: 祝日名（10px・`--sun`・1行でマスの幅の 60% まで。はみ出す分は「…」）（参考画像 2・D12）。S は出さない。
- 下の真ん中: 件数（7.6）。L・M は「4 / 3」（等幅 22px。仕事の数は `--work-text`、「/」は `--text-faint`、プライベートの数は `--private-text`）。S は「4/3」（等幅 14px・空白なし）（要件・D24）。
- 片方が 0 なら、その数を「0」（`--numeral`。4.5 の例外）。両方 0 の日（何も無い日も、全部完了した日も）は何も書かない（D24）。
- 休みの日はマスの地を `--off-fill`（7.4）。

### 9.3 押した時

- L・M: 仕事の数字・プライベートの数字は別々のボタン（押せる所は数字の周り 34px 四方以上）。押すとその日のデイリーへ移り、押した側の区切りとその区分の予定を 1.2秒目立たせる（要件・D24。11.2）。マスのほかの所を押すとその日のデイリー（目立たせない）。PC はマスに乗せると地を `--surface-2` にする。
- S: マスのどこを押してもその日のデイリー（D24）。
- 休みを付ける状態の間は 9.5。

### 9.4 スワイプ

- S・M の指の操作で左右になぞると前後の月（3.7）。

### 9.5 休みを付ける状態

（Q19）

- 操作の列の［休み］を押すと「休みを付ける状態」になる。［休み］は押した状態（地 `--today-bg`・字 `--on-primary`・`--today-ring` の輪。7.3）になり、操作の列のすぐ下に帯「休みを付ける: 日付を押すと休みが付いたり外れたりします ［終わる］」（地 `--accent-soft`・高さ 36px）を出す。
- その間は、どのマスを押しても（数字を押しても）デイリーへは移らず、その日の休みが付いたり外れたりする。マスの枠を 1px の点線（`--accent`）にして、押せることを示す。
- ［休み］をもう一度押す・［終わる］・Esc・モードを替える、のどれかで終わる。‹ › でほかの月へ移っても終わらない（月をまたいで続けて付けられるように）（開発）。

### 10.4 7日を縦（S）

（Q10）

- いちばん上に段の名札の行（高さ 24px・上に固定）: 左半分に「WORK 仕事」、右半分に「PRIVATE プライベート」（アイコン付き）。

### 11.3 タイムスケジュール（右）

- 0:00〜24:00（D28）。1時間の高さは L・M 48px、S 44px。左に幅 48px の時刻の欄（等幅 11px・`--text-faint`。「0:00」〜「23:00」を各時間の上の端に）（参考画像 5）。
- **時間の縞**（参考画像 4・5）: 偶数の時（0・2・4…）は `--surface`、奇数の時は `--stripe` の地。各時間の上に 1px の `--rule`、12:00 の線は 1px の点線（`--rule-strong`）、0:00 の線は 2px（`--rule-strong`）。
- **今の時刻の線**（今日だけ）: 2px の `--accent` の横線と、時刻の欄の端に直径 8px の丸。60秒ごとに動かす（D28）。
- **開いた時の位置**: 今日は今の時刻の 60分前を上の端に、ほかの日は 7:00 を上の端に（D28）。
- **1日の予定**: 開始時刻から終了時刻までの高さの枠（最小 24px）。開始時刻だけの予定は `min(開始 + 30分, 24:00)` までの枠（D28・6.4）。地は土台の色（ディープダークは 1px の `--border` の枠も。4.5）、ラベルの一辺 4px、角丸 6px、余白 上下 4px・左 10px・右 6px。左上に点線の丸（16px。4.11。押すと完了。D29）、件名（12px・500。入るだけ）、時刻（等幅 11px）。右上に区分のアイコン（`BagIcon`／`HomeIcon`。12px）（D28）と、ロック・AI の印。押すと詳細。
- **日をまたぐ時刻のある予定**（Q13）: 期間の各日に、その日の部分（初日は開始時刻〜24:00、間の日は 0:00〜24:00、最終日は 0:00〜終了時刻）を出す。
  - 開始のカード（高さ 40px。件名＋`11/9 10:00〜11/11 15:00`。2日目からは件名の頭に「‹ 」）を、その部分の始まりの時刻の所に出す。始まりの時刻が見えている範囲より上にスクロールされたら、その部分が見えている間は、カードを見えている範囲のいちばん上に貼り付けて出す（`position: sticky`）（Q13: 見えているいちばん早い時刻の所に開始のカードをいつも出す）。
  - カードの下から部分の終わりまで、太さ 2px の線（色は 7.8）。最終日は終了時刻の所に●（10px）、ほかの日は 24:00 の所に下向きの矢印（「＞」を 90度回した物）。
- **重なり**（D28）: 時間が重なる予定（日をまたぐ予定の部分を含む）をまとめ、始まりの早い順（同じなら長い順）に、空いているいちばん左の列に入れる。列の幅はまとまりの中の列の数で等分する。列は L・M で4つ、S で3つまで。それより多い分は、最後の列に「+2」の札（等幅 11px）を、隠れた予定のいちばん早い時刻の所に出し、押すと隠れた予定の一覧（押すと詳細）を小さく開く。
- **空いた所を押す**（D31）: 登録の画面（12.2）を、日付はこの日、開始時刻は押した所を 30分単位に切り捨てた時刻、終了時刻は `min(開始 + 60分, 24:00)`、区分は仕事で開く。
- 枠をなぞって時刻を変える操作は作らない（D28）。

## 12. 予定の登録・詳細・完了・ロック・複製・削除

### 12.1 すばやく足す

- ウィークリーの各日・各段の「＋」、デイリーの各区切りの「＋ 予定を足す」を押すと、その場に1行の入力欄が開く（D31）。件名を打って Enter で足す。日付（開始日）と区分は押した場所で決まり、時刻は無し、`origin: 'calendar'`。
- 足した後も入力欄は開いたままで、続けて足せる。Esc・入力欄の外を押すと閉じる。日本語の変換中の Enter では足さない（`isComposing`）（D42）。書きかけは `diary-studio:draft:quick:{日付}:{区分}` に控える。
- 細かい項目は、後でカードを押して詳細で足す（D31）。

### 12.2 登録の画面

開く所: 操作の列の［＋ 登録］（N キー）、デイリーのタイムスケジュールの空いた所、Favorite の「予定にする」。L は真ん中の小さな画面、M・S は下からのシート（D32）。題は「予定を登録」。

| 順 | 欄 | 中身 | 初めの値 |
|---|---|---|---|
| 1 | 件名 | 1行の入力欄（200字まで）。開くとここにフォーカス | 空（Favorite からは1行目） |
| 2 | 区分 | ［かばん 仕事｜家 プライベート］の切り替え | 仕事（Q1）。開いた場所で決まる時はその区分 |
| 3 | 日付 | 「開始日」〜「締め切り日」。押すと小さな月のカレンダー（日曜始まり・今日の印・土日祝の色。L は下に開く小窓、S はシート）。締め切り日の欄の下に「空なら1日だけ」（D33）、入れた時は［×］で消せる | 開始日: デイリーからはその日、ほかは今日（D31）。締め切り日: 空 |
| 4 | 時刻 | 「開始」〜「終了」。押すと 0:00〜23:55 の 5分刻みの一覧（終了の一覧は最後に 24:00 も。9:00 の所を見せて開く）。打てば `9:07` のように1分単位も入る（D33・6.4） | 空（タイムスケジュールからは押した時刻と 60分後。24:00 まで） |

- 書きかけのまま閉じようとした時（件名かメモに文字がある時）は「書きかけを捨てますか？［捨てる］［戻る］」と確かめる（開発）。
- 登録すると閉じ、その予定のカード（見えていれば）を 1.2秒目立たせる（4.9）。お知らせは出さない（開発）。
- 必ず入れるのは件名・開始日・区分の3つ（開始日と区分は最初から入っている）（D32・I7）。

### 12.3 詳細の画面

カード・行・Task View の行などを押すと開く。開き方は 3.8（カレンダーからは真ん中・シート、リストからは右の列のパネル・シート）。題は、カレンダーから開いた時「予定」、Task List から開いた時「タスク」（D46）。

- **上の列**: 点線の丸と「完了にする」／「完了」（押すと切り替え）、右に［複製］、「…」（［削除］）、［×］。
- **欄**: 12.2 と同じ並び（件名 → 区分 → 日付 → 時刻 → 詳しく）。直したそばから自動で保存する（文字の欄は 0.6秒止まった時・フォーカスを外した時、日付・切り替えはすぐ）（D32・NS の DraftInput）。
- **list 生まれのタスク**: 開始日も任意。日付の欄の下に、今どう出るかを1行で出す（Q2・I7）:
  - どちらも空: 「カレンダーには出ません（Task List だけ）」
  - 開始日だけ: 「開始日だけではカレンダーに出ません。締め切り日を入れるとカレンダーに出ます」
  - 締め切り日だけ: 「11/20（金）の1日の予定としてカレンダーに出ます」
  - 両方: 「11/10（火）〜11/20（金）の予定としてカレンダーに出ます」
- **カレンダーに出ていない項目の時刻**: list 生まれの①④（カレンダーに出ていない物）では時刻の欄を押せなくし、「締め切り日を入れると時刻を入れられます」と添える。締め切り日を消してカレンダーから外れた時、時刻は消さずに残すが、出し方には使わない（締め切り日をまた入れると戻る）（D37・開発）。
- **詳しくの「Task List にも出す」**: calendar 生まれは切り替えられる。list 生まれは、カレンダーに出ている時だけ切り替えられ（オフ＝「Task List から外す」）、出ていない時は切り替えを押せない（6.3）。
- **メモ**: 入力欄から離れている間は文章として出し（URL は押せるリンク。新しいタブ・`rel="noopener noreferrer"`）、押すと入力欄になる（D33。書式は付けない）。
- **下の行**（12px・`--text-faint`）: 「作った 2026/11/10 09:12」「完了 2026/11/12 18:03」、コネクタから来た物は「Claude が追加（メール: 来週の打ち合わせ）」（`ai`・`via`）（I6）。

### 12.4 入力の決まり（まとめ）

| 決まり | 中身 | 出典 |
|---|---|---|
| 必ず入れる | 件名・区分。calendar 生まれは開始日も | 要件・I7 |
| 締め切り日 | 空なら開始日の1日。開始日より前を選ぶと、開始日もその日にそろえる（1日の予定。6.3） | 要件・D33・開発 |
| 開始日を締め切り日より後にした | 締め切り日を開始日にそろえる（1日の予定） | D33 |
| 時刻 | 開始だけは入れられる。終了だけは入れられない（開始を空にすると終了も消える） | D33 |
| 1日の予定で終了 < 開始 | 時刻を入れた・直した時は、翌日までの2日にまたがる予定にする。日付を動かしてこの形になる時は、その日付にはできない（6.4） | D33・開発 |
| 終了 = 開始 | 終了時刻を空にする（開始時刻だけの予定） | 開発 |
| 終了に 00:00 | 24:00（その日の終わり）と読む。終了の一覧には 24:00 もある | 開発 |
| 時刻の刻み | 一覧は 5分刻み、打てば1分単位 | D33 |
| 件名 | 1〜200字 | 開発 |
| 依頼者 | 0〜60字 | 開発 |
| メモ | 制限なし | 要件・D9 |
| 日が過ぎても完了していない予定 | 動かさず、知らせない（マンスリーの過去の日に残る数字が目印） | D33 |

### 12.5 完了

- 予定全体で1回（Q3）。どの日のカード・行で押しても、期間全体が完了になる。
- 押せる所: 詳細の上の列、ウィークリーのカードの左上の丸、デイリーのリストの行頭の●、タイムスケジュールの予定の左上の丸、Task List の行のチェック（D29・Q6）。もう一度押すと戻る。
- 完了にすると `done = true`・`doneAt = 今`・`doneOn = 今日`、戻すと3つとも消す（Q3・Q23）。
- 見え方は 7.9。ウィークリーのカードの丸・デイリーのリストの●・タイムスケジュールの丸で完了にした時は、画面の下に「『件名』を完了にしました［元に戻す］」を 6秒出す（D14。完了を外した時は出さない）。詳細の中のチェック（その場で切り替わりが見えるため。開発）と、Task List のチェック（右の列のリストなので Q22 のおすすめ案の中身）では出さない。

### 12.6 ロック

- 詳細の「詳しく」の切り替えでオン・オフする（D30）。オンの間はウィークリーで動かせない（7.10・7.11）。詳細ではいつでも直せる（要件）。

### 12.7 複製

日付の決まっていない繰り返しの予定（「毎月あるが日は不定」など）を手早く作るため（Q5）。1日ずつ完了にしたい物（Q3 のおすすめ案の中身）や、毎日同じ時刻の数日間の予定（例: 5日間の研修。Q13 のおすすめ案の中身）も、1日ずつの予定にして複製で作る。繰り返しの予定そのものは作らない。

- 詳細の［複製］を押すと、小さな画面「複製する日を選ぶ」を開く。中は元の予定と同じ日付の欄（開始日〜締め切り日）で、最初は空（I4）。
  - calendar 生まれ: 開始日を選ぶ（必須）。元が複数日の予定なら、開始日を選んだ時に締め切り日を「元と同じ日数」になるよう自動で入れる（直せる）（開発）。
  - list 生まれ: 開始日・締め切り日とも任意（6.3 の4通りのとおりに出る）。
- ［複製する］で新しい項目を作る。写す物: 件名・区分・ラベル・依頼者・開始時刻・終了時刻・ロック・メモ（I4）と、生まれ・Task List に出すか。写さない物: 日付（選んだ日にする）・完了（未完了にする）・作った日時（今）・`by`／`ai`／`via`（手で作った物にする）。
- 作った後は画面の下に「11/17（火）に複製しました［開く］」（6秒）。［開く］で新しい予定の詳細へ。

### 12.8 削除

- 詳細の「…」→［削除］（横に払って消す操作は作らない）（D13）。
- カレンダーに出ている項目は確かめてから消す: 「『件名』を削除しますか？」「ゴミ箱に移します。30日後に完全に削除されます（それまではゴミ箱から元に戻せます）。Task List からも消えます。」（Task List に出ていない時は最後の1文を出さない）（D13・Q6）。
- カレンダーに出ていないタスク（Task List だけ）は確かめずに消し、「『件名』を削除しました［元に戻す］」（6秒）（D13）。
- どちらから消しても、カレンダーと Task List の両方から消えてゴミ箱へ入る。戻すと両方に戻る（Q6 のおすすめ案の中身）。

## 13. Task List

口頭などで突発的に頼まれたことを、とりあえず放り込む領域（要件）。余裕ができたらカレンダーへ、即日の物はここで消し込む。

### 13.1 Task List に出る物

- `listed` が true の項目（6.3）。Task List で入れた物（list 生まれ）と、カレンダーで入れて「Task List にも出す」をオンにした物（D38）。
- Task List とカレンダーは同じ1件で、どちらで直しても完了にしても両方に出る（Q6・D3）。

### 13.2 入力欄

- 見出しの下に、いつも1行の入力欄（自動で高さが伸びる。プレースホルダ「タスクを入れる…」）（D37・D42）。
- 入力欄の下に小さなボタン（`btn-sm`・`btn-ghost`）:
  - ［開始日］: 今日・明日・日付を選ぶ（Q2）。
  - ［締め切り日］: 今日・明日・今週金曜・日付を選ぶ（D37）。「今週金曜」はその週（日〜土）の金曜。今日が土曜の時は「来週金曜」と出して次の金曜にする（開発）。
  - ［依頼者］: 小さな入力欄が開き、前に入れた名前を候補に出す（直近 365日に使った名前を、使った回数の多い順に8つまで）（D37）。
  - 決めた値はチップ（「開始 11/10 ×」「〆 11/20 ×」「田中さん ×」）で出し、×で外せる。
- Enter で足す（日本語の変換中は足さない）。PC の Shift+Enter は改行。2行以上なら、1行目を件名、2行目からをメモにする（D37）。
- 足すと: `origin: 'list'`・`kind: 'work'`（Q7）・`listed: true`、開始日・締め切り日・依頼者は選んだ値。入力欄とチップは空に戻り、フォーカスは入力欄に残る（続けて足せる）。足した行を 1.2秒目立たせ（4.9）、右の列の中で見える所までスクロールする。
- 締め切りは日付だけ。時刻はカレンダーの詳細で入れる（D37）。
- 書きかけは `diary-studio:draft:task` に控える（D42）。

### 13.3 行

- **L**（右の列。左から。要件の「締め切り日｜依頼者｜要件」の並び）:

  | 欄 | 幅 | 中身 |
  |---|---|---|
  | 区分の印 | 16px（押せる所は行の高さいっぱい） | 線のアイコン（`BagIcon`＝仕事・`HomeIcon`＝プライベート。16px・`--text-muted`）。押すと区分が入れ替わる（Q7） |
  | チェック | 24px（押せる所は 40px 四方を目安。4.11） | 点線の丸（4.11） |
  | 締め切り日 | 40px | 等幅 12px。カレンダーに出ている物は期間（6.3）で出す: 1日なら「11/20」、複数日なら「11/10〜」（10px・`--text-faint`）の下に「11/20」。カレンダーに出ていない物は、開始日だけ「11/10〜」、どちらも無ければ「—」（`--text-faint`）（Q2 のおすすめ案の中身・開発）。締め切りを過ぎた色・今日の太字は、期間の終わり `to`（締め切り日。calendar 生まれで締め切り日が空なら開始日）で決め、`to` が今日より前で済んでいない物は字を `--overdue`、今日の物は太字（600）（D38）。押すと日付のメニュー（13.5） |
  | 依頼者 | 48px（名前がある行だけ。空の行は詰める） | 12px・1行（はみ出す分は「…」）。押すとその場で直す（候補付き） |
  | 要件（件名） | 残り（依頼者ありで約 124px、なしで約 176px） | 14px・2行まで。押すとその場で直す（1行の入力欄。Enter・外を押すと保存） |
  | … | 欄を取らない | 件名の右上に重ねて出す。PC は行に乗せた時だけ、指の端末ではいつも出す |

  欄の間は 4px（開発。右の列 300px から左右の余白 16px ずつを引いた 268px に、要件の「締め切り日｜依頼者｜要件」の並びを保って収める）。
- **M・S**（D37）: 2行の行にする。上の行に小さく「〆11/20・田中さん」（等幅の日付＋依頼者。11px・`--text-muted`。開始日があれば「11/10〜11/20」）、下の行に件名を大きく（15px）。左に区分の印とチェック、右に「…」。
- 行の下に 1px の `--rule`。区分は行の背景のマーカー（4.3）と左の区分の印（押すと切り替わる。Q7）で見分ける（Q14・Q7）。

### 13.4 並び・済み

- 並び（D38）: カレンダーに出ている物を期間の終わり `to` の近い順（同じ日は入れた順）、その下にカレンダーに出ていない物（①の日付の無い物と④の開始日だけの物）を新しい順。仕事とプライベートは混ぜて出す（calendar 生まれで締め切り日が空の物も、`to` ＝開始日で上の並びに入る。開発）。
- 済み（Q22）: チェックすると斜線とグレー（`--done-text`）になり、リストの下の「済み n件」（ふだんは畳む）へ沈む。チェックを外すと元の位置へ戻る。移った先の行を 1.2秒目立たせる（4.9。「済み」が畳まれている時は「済み n件」の区切りを目立たせる）。知らせは出さない（Q22 のおすすめ案の中身）。
- 済んでから7日たった物は Task List に出なくなる（データは残り、カレンダーと Task View には完了した予定として出る）（Q22 のおすすめ案の中身）。
- 見出しの数は、済んでいない物の数。

### 13.5 行の操作

- 「…」メニュー:
  - ［詳しく］: 詳細（12.3）を右の列のパネル（S・M はシート）で開く。
  - ［日付を決める］: カレンダーに出ていない項目（list 生まれの①④）だけ。小さな月のカレンダーで日を選ぶと締め切り日になり、その日の1日の予定としてカレンダーに出る（開始日があってその日以前なら期間になる）（D39・Q2）。
  - ［Task List から外す］: カレンダーに出ている時だけ（6.3・Q6 のおすすめ案の中身）。外すとカレンダーにだけ残る。
  - ［削除］: 12.8 の決まり（カレンダーに出ている物は確かめる、出ていない物は確かめずに［元に戻す］付きで消す）。
- 締め切り日の欄のメニュー: 締め切り日を 今日・明日・今週金曜・日付を選ぶ・なし、開始日を 日付を選ぶ・なし、［カレンダーで見る］（カレンダーに出ている時。その日のデイリーへ）。list 生まれで締め切り日を「なし」にすると、カレンダーから消えて Task List にだけ残る（Q2）。calendar 生まれでは、開始日の「なし」は出さず（開始日は必須。I7）、締め切り日の「なし」は「1日の予定にする（締め切り日を消す）」と出す（開発）。

### 13.6 カレンダーとの連動

- 同じ1件なので、件名・依頼者・日付・メモ・完了はどちらで変えても両方に出る（Q6）。
- カレンダーのウィークリーで〆のカードを別の日へ動かすと、締め切り日がその日になる（Q2 のおすすめ案の中身。7.11）。
- list 生まれの締め切り日を消すと、カレンダーから消えて Task List にだけ残る（Q2。calendar 生まれは開始日の1日の予定になる。6.3）。
- **L で行をカレンダーへドラッグ**（D39）: マウスで行を掴み（5px 動かす）、マンスリーの日のマス・ウィークリーの同じ区分の段の日・デイリーの同じ区分の区切りへ落とす。区分は変えない（違う区分の段には落とせない）。日 D へ落とした時（開発）:
  - カレンダーに出ていない物（①④）は `due = D`（④で開始日が D より後なら、開始日も D にそろえる）。
  - カレンダーに出ている1日の予定は、7.11 の表の1日の予定と同じく日ごと動かす（開始日も締め切り日も D）。
  - 複数日の予定は締め切り日だけを D にする（D が開始日より前の日には落とせない）。
  - 6.4 で動かせない日（1日の予定で終了 < 開始になる日）には落とせない。
  - ロック中の項目は、Task List の行からもドラッグできない（掴もうとすると 7.10 と同じく揺れる）。
  - 動かした後は「締め切り日を 11/12（木）にしました［元に戻す］」（1日の予定を日ごと動かした時は「11/12（木）へ移しました［元に戻す］」）（6秒）。指の端末ではドラッグできない（［日付を決める］・詳細を使う）。

## 14. Routine List

毎日・毎週・毎月・四半期・毎年の、決まった繰り返しの作業を出すだけの領域（要件・Q15）。通知・アラートは出さない。カレンダーの数字と Task View には出さない（D41）。

### 14.1 種類と指定

| 種類 | 指定（任意） | 項目の右に小さく出す（11px・`--text-faint`） |
|---|---|---|
| 毎日 | なし | — |
| 毎週 | 曜日（いくつでも選べる。→22 の I2） | 「月」「月・木」 |
| 毎月 | 日（1〜31） | 「25日」 |
| 四半期 | なし（I2） | — |
| 毎年 | 月日 | 「3/15」 |

- いつも全部を出す（その日だけ出す、はしない）（I2）。

### 14.2 つくり

- 見出し（3.6）の右に［すべて開く］／［すべて畳む］（1つのボタンで切り替え。どれか1つでも畳んでいれば「すべて開く」）（要件・D41）。
- 入力欄（プレースホルダ「ルーチンを足す…」）の左に種類の切り替え［日｜週｜月｜四半期｜年］（`segmented` の小さい物。前に選んだ種類を端末ごとに覚える）、右に［指定］（毎週・毎月・毎年の時だけ。押すと小さな窓: 毎週は7つの曜日のボタン、毎月は 1〜31 の選択、毎年は月と日の選択）。Enter でその種類のいちばん下に足す（D41）。
- **種類ごとのかたまり**: 毎日 → 毎週 → 毎月 → 四半期 → 毎年 の順で固定（D41・I2）。見出し（高さ 32px）に種類の名前（13px・500）、済んだ数／全部（等幅 12px・`--text-faint`。例「2/5」）、畳む・開くの山形。D41 の「今の期間（毎週 11/8〜11/14）」は、指定のある項目ごとに戻る日が違うため出さない（Q15・I2）。畳んだ・開いたは端末ごとに覚える。項目の無い種類は見出しを不透明度 0.5 で出し、右に「＋」（押すとその種類を選んだ入力欄にフォーカス）（D41）。
- **行**: 点線の丸のチェック、件名、右に指定（14.1）。済んだ行は、そのかたまりの下の「済み n件」（ふだんは畳む）へ沈む（Q22）。PC では済んだ行に乗せると「11/16（月）に戻ります」（次の戻る日。14.3）と出す（開発）。
- Routine List の中でいつでも直せる（Q15）: 件名を押すとその場で直す。「…」→［詳しく］で、件名・種類・指定・［削除］のパネル（S・M はシート）。種類や指定を変えると、済みかどうかも新しい決まりで計算し直す（チェックの記録はそのまま）。
- 並べ替え: かたまりの中だけ。PC は行に乗せた時に出るつまみ（`GripIcon`）でドラッグ、指の端末は 0.4秒の長押しで掴む（D41）。
- 削除: 「…」→［削除］。確かめずに消し、「『件名』を削除しました［元に戻す］」（6秒）。チェックの記録もいっしょにゴミ箱へ（D13）。

### 14.3 済みと戻る時

- チェックすると、その日（今日）を `routineChecks` に記録する（D7）。チェックを外すと、いちばん新しい「戻る日」以後の記録を消す。
- **済み** = いちばん新しいチェックの日が、いちばん新しい「戻る日」以後であること。0時に外す書き込みはせず、見るたびに計算する（どの端末で開いても同じになる）（D7）。
- **戻る日**（その日の 0時にチェックが外れる。I2）:

  | 種類 | 指定 | いちばん新しい戻る日（今日以前） |
  |---|---|---|
  | 毎日 | — | 今日 |
  | 毎週 | なし | 今日以前でいちばん近い日曜 |
  | 毎週 | 曜日 | 今日以前でいちばん近い、指定の曜日のどれかの日 |
  | 毎月 | なし | 今月の1日 |
  | 毎月 | 日 d | 今月の d 日（今月に無ければ今月の最終日）が今日以前ならその日、まだなら先月の d 日（無ければ先月の最終日） |
  | 四半期 | — | 今の四半期（1・4・7・10月）の1日 |
  | 毎年 | なし | 今年の1月1日 |
  | 毎年 | 月日 m/d | 今年の m/d（無ければその月の最終日。2/29 なら平年は 2/28）が今日以前ならその日、まだなら去年の m/d |

- **次の戻る日**（今日より後でいちばん近い戻る日。14.2 の「11/16（月）に戻ります」に使う）（開発）: 毎日＝明日、毎週（指定なし）＝次の日曜、毎週（曜日）＝今日より後でいちばん近い指定の曜日、毎月（指定なし）＝来月1日、毎月（d）＝今月の d 日（無ければ月末）が今日より後ならその日、でなければ来月の d 日（無ければ月末）、四半期＝次の四半期の1日、毎年（指定なし）＝来年1月1日、毎年（m/d）＝毎月と同じ考え方で今年か来年の m/d（無ければその月の最終日）。
- 例: 毎週（月）を水曜 11/11 にチェック → 月曜 11/16 の 0時に外れる。毎月（25日）を 11/26 にチェック → 12/25 の 0時に外れる。毎月（31日）は 11月は 11/30 に戻る。毎月（31日）を 2027/1/31 にチェック → 2/28 の 0時に外れる（2028年は 2/29）。2/28 にチェック → 3/31 の 0時に外れる。1/30 にチェック → 1/31 の 0時に外れる。

## 16. MIM（most important memo）

### 16.1 開き方

- 上の列: ［‹ カレンダーに戻る］、等幅の「MIM」（15px・500）と小さく「most important memo」、右に［＋ メモ］［印刷］。

### 16.2 メモの一覧

- L・M: 左に一覧（幅 260px）、右に選んだメモ。S: 一覧 → 押すとメモの画面（`#/mim/{id}`。戻るで一覧へ）。
- 一覧の上に検索の欄（16.6）。各行: 題名（14px・500。空なら「無題」）と本文の1行目（12px・`--text-faint`・1行）。選んでいる行は地 `--accent-soft`。
- メモは何枚も作れ（Q16）、手で並べ替える（PC はつまみでドラッグ、指の端末は長押し 0.4秒）（Q16 のおすすめ案の中身）。
- ［＋ メモ］で新しいメモを一覧のいちばん上に作り（`order` は今のいちばん小さい値 − 1）、題名にフォーカスする。メモが無い時は「大事なリンクやパスワード、いざという時の手順を入れておく所です。」と［＋ メモ］。

### 16.3 メモの中身

- **題名**: 枠の無い入力欄（20px・600。プレースホルダ「無題」）。
- **本文**（Q16）: 長さの制限なし・自動保存（0.6秒止まった時・フォーカスを外した時）。読む表示と直す表示がある。読む表示では、URL は押せるリンク、空でない各行の右に［コピー］（PC は行に乗せた時だけ、指の端末はいつも。16px のアイコン・押せる所 28px）（Q16 のおすすめ案の中身）。本文を押す（リンク・コピー以外）か［直す］で直す表示（自動で高さが伸びる入力欄）、Esc・外を押すと読む表示に戻る。
- **削除**: 「…」→［削除］。確かめてから（「『題名』を削除しますか？」）ゴミ箱へ（D13）。

### 16.4 伏せる欄

（Q16・Q17）

- 見出し「伏せる欄」と［＋ 伏せる欄］。いくつでも足せる。
- 1つの欄: 名前（入力欄。プレースホルダ「名前（例: パスワード）」）、中身（ふだんは「●●●●●●●●」の8つの●。長さは見せない）、［見る］（目のアイコン）、［コピー］、「…」（［削除］）。
- ［見る］を押した時だけ中身を出す（その間は中身を直せる入力欄）。もう一度押す・30秒たつ・ほかのメモへ移る・MIM を閉じる・アプリが裏に回る、のどれかでまた伏せる（Q17・開発）。
- ［コピー］は見せずに中身を写す。「『パスワード』をコピーしました」と出す（中身は出さない）。
- 中身は検索の対象にしない（16.6）。

### 16.5 QR の欄と QR の出し方

（Q16・Q25・I5）

- 見出し「QR の欄」と［＋ QR の欄］。1つのメモにいくつでも足せる（I5）。中身が何か（パスワード・ID・URL）はアプリでは区別しない（Q16）。伏せない（Q25・I5）。
- 1つの欄: 名前（任意・40字まで）、中身（自動で高さが伸びる入力欄・200字まで）、右下に残りの字数（「残り 37字」。等幅 11px。0 になったら `--overdue`）、［QR］（中身が空の間は押せない）、［コピー］、「…」（［削除］）。200字を超えて貼り付けた時は 200字までにして「200字までにしました」と出す（I5）。
- **QR を出す**: 画面いっぱいの重なり（地は `rgb(0 0 0 / 85%)`。どの外観でも同じ）の真ん中に、白い地（`--qr-bg`）に黒（`--qr-fg`）の QR を大きく出す（I5）。大きさは `min(画面の幅, 画面の高さ − 120px) − 32px`（最大 560px）。周りの白い余白は4マス。誤り訂正は M（`uqr` の `encode(text, { ecc: 'M', border: 4 })` を SVG の四角で描き、`shape-rendering: crispEdges`）。QR の下（白い地の中）に名前と字数（黒・14px）。
  - どこを押す・Esc で閉じる。出している間は画面が暗くならないよう Wake Lock（`navigator.wakeLock.request('screen')`。使えない端末では何もしない）を取り、閉じたら放す。
  - 200字（日本語・誤り訂正 M）はバージョン 19（93マス四方。周りの白い余白4マスを入れて 101マス）になる（調査で実測）。画面いっぱいに出せば読める見込みだが、これは経験則なので、段階4で iPhone と Android のカメラで実際に読めるか確かめる（調査・21）。

### 16.6 検索

- 一覧の上の検索の欄で、題名・本文・伏せる欄の名前・QR の欄の名前と中身から探す。伏せる欄の中身は探さない（Q16 のおすすめ案の中身）。
- 全角と半角・英字の大文字と小文字は同じとみなし（`NFKC` にして小文字にする）、空白で区切った語をすべて含むメモだけを出す（D36 と同じ決まり。`src/domain/search.ts`）。当てはまらなければ「当てはまるメモがありません」。

### 16.7 印刷・案内・オフライン

- ［印刷］（D43）: 今のメモ（題名・本文・伏せる欄（中身を出して）・QR の欄（中身と QR））を、白い地に黒の字で印刷する（印刷用の CSS。ほかの画面の部分は出さない）。押した時に「伏せる欄の中身も紙に出ます。印刷しますか？」と確かめる。
- 案内（D43・Q17 のおすすめ案の中身）: 一覧のいちばん上に「Google アカウントのパスワードは MIM だけに置かず、紙などにも控えてください（ログインできないと MIM も開けません）。銀行など特に大事な物は、パスワード管理アプリとの併用をおすすめします。」と［閉じる］（閉じたら、この端末では出さない）。
- 一度開いた端末なら電波が無くても読める（端末の中のデータ）（D43）。

### 16.8 守り

- 合言葉の鍵はかけない。守りは Google ログインと端末の画面ロックに任せる（Q17）。
- 後で作るコネクタからは一切読めない（表を分け、アクセスルールでも読ませない）（D8・Q17・I6）。
- バックアップに含めるかを選べる（6.16）。

| 版 | データの形の版 `DATA_MODEL`（`meta/app`）を最初から使う（コネクタは版が違えば書かない。NS） | 6.10 |

### 19.3 受け取り箱の中身と、内容から作る id

- `target` ごとの `payload`（コネクタのツールの入力と同じ形にする）:

  | target | 項目 | 決まり |
  |---|---|---|
  | `item`（予定） | `kind`（必須。`work`／`private`）、`title`（必須・1〜200字）、`start`（必須・`YYYY-MM-DD`）、`due`・`startTime`・`endTime`・`label`・`requester`・`memo`・`listed`（任意） | 6.3・6.4・12.4 の決まりで確かめる。区分は必ず付く（要件。無ければ `invalid`） |
  | `task`（タスク） | `title`（必須）、`kind`（任意。無ければ `work`。Q7）、`start`・`due`・`requester`・`memo`（任意） | list 生まれとして取り込む |
  | `favorite`（やりたいこと） | `text`（必須） | |
  | `trash`（ゴミ箱へ移す依頼） | `id`（必須。そのコネクタで足した記録の id） | 19.4 で確かめる（D48） |

  - `label` はキー（`sky-l`）か、設定で付けた呼び名（全角と半角・大文字と小文字を同じとみなす）。見つからなければラベルなしで取り込み、`message` に「ラベル『…』が見つからないので、ラベルなしで入れました」と残す。
  - 長さ: `memo`・`text` は 100,000字まで、`via` は 500字まで、`ai` は英小文字・数字・`-` の 20字まで、受け取り箱の1件の JSON は 200,000字まで（NS のコネクタの上限と同じ。分割文書を書かせないため）。
- **内容から作る id**（`src/domain/derivedId.ts`。NS の `derivedId` と同じ考え方）: `{ target, payload }`（文字の前後の空白を除き、キーを並べ替えた物。`ai`・`via` は含めない＝別の AI・別のメールから同じ予定が来ても1件）の指紋 `h`（`hashJson`）から、作る記録の id を `c{e|t|f}-{h}`（e＝予定・t＝タスク・f＝やりたいこと）にする。受け取り箱の記録そのものの id は、コネクタが作るランダムな id（`x-{uuid}`。6.14）で、内容からは作らない（同じ内容が2つの AI から届いても、受け取り箱の文書がぶつからないように。二重の登録は 19.4 で防ぐ）。

### 19.4 取り込みの流れ

- **誰が・いつ**: 同期を受け持つタブが、受け取りのたびと起動の最初の同期の後に、`status: 'new'` の受け取り箱の記録を `createdAt` の順に取り込む。
- **1件ずつ**:
  1. 19.3 の決まりで確かめる。合わなければ `status: 'invalid'`・`message` に理由（日本語）。
  2. 作る記録の id がもうあれば `duplicate`。ゴミ箱にある・クラウドの削除の印がある id なら `previously_deleted`（削除した物は戻ってこない。NS。内容から作った id の削除の印は片付けずに残す。6.11）。
  3. どちらでもなければ記録を作る（`by: 'connector'`・`ai`・`via` を写す）→ `added`・`resultId`。
  4. 記録を作るのと受け取り箱の書き換え（`status`・`resultId`・`message`・`processedAt`）を、端末の中の1つの書き込みで行う（あとは通常の同期で送る）。
- **ゴミ箱へ移す依頼**（`target: 'trash'`。D48・NS SPEC-2.md の 15. と同じ考え方）: `payload.id` の記録が予定・タスク・やりたいことの表にあり、`by: 'connector'` で、まだゴミ箱に無ければ、作者が消した時と同じ形でゴミ箱へ移し（ゴミ箱の件に `by: 'connector'`・`ai` を付け、ゴミ箱の画面に「AI の依頼」の札を出す）、`status: 'trashed'`・`resultId` にその id。手で作った記録・見つからない記録・もうゴミ箱にある記録は移さずに `invalid`（`message` に理由）。ゴミ箱の件と中身の id は依頼の id から作る（`te-{受け取り箱の id}`・`tr-{受け取り箱の id}`。2台が同じ依頼を処理しても1件になる。NS）。
- 2台の端末が同時に同じ記録を取り込んでも、作る記録の id が同じなので1件にまとまる。
- 取り込んだら、画面の下に「Claude から予定を2件・やりたいことを1件受け取りました［見る］」（6秒。［見る］で設定の「AI から届いた物」）。ゴミ箱へ移した時は「Claude の依頼で、予定を1件ゴミ箱へ移しました（30日はゴミ箱から戻せます）」。通知・音は出さない（D34）。
- 取り込んで30日たった受け取り箱の記録は消す（6.14）。

### 19.5 コネクタ（後で作る）

NS のコネクタ（`connector/`・docs/CONNECTOR.md・SPEC-2.md の 7.）の作りを流用する（D48・調査）。

- Cloudflare Workers の無料プランに置くリモートの MCP サーバー。OAuth は `@cloudflare/workers-oauth-provider`。Claude は公開の名札（CIMD）で受け付け、同意は毎回聞く。連携は NS と同じ「同意を始めたブラウザ」と「アプリにログインしている持ち主」の両方がそろって完成する仕組み（`config/connector`）。
- コネクタは自分の匿名の Firebase アカウントで動き、アクセスルールで「`mimNotes` とゴミ箱を除く記録を読む」「`inbox:{id}` を `status: 'new'`・`by: 'connector'` で新しく作る」だけを許す。書き換え・削除・チェックはしない（足すだけ。ゴミ箱へ移す依頼も受け取り箱に作るだけ。D48）。
- ツール（名前は `ds_` で始める。説明は特定の AI に限らない書き方）: 読む＝`ds_status`・`ds_list_items`（期間を指定。93日まで）・`ds_list_tasks`・`ds_list_routines`・`ds_list_favorites`、足す＝`ds_add_items`・`ds_add_tasks`・`ds_add_favorites`（1回 50件まで）、ゴミ箱へ移す依頼＝`ds_move_to_trash`（`destructiveHint`。「作者が頼んだ時だけ使う」とツールの説明に書く）。読む物には `readOnlyHint`。
- **受け付ける AI の一覧**: 最初は Claude だけ。Perplexity は後で足す（DCR を受け付け、Perplexity の戻り先 `https://www.perplexity.ai/rest/connections/oauth_callback` を許し、`client_secret` を返し、登録の時に送られてくる戻り先の数を5つまでに絞らず（Perplexity は5つより多く送ってくる。そのうち許すのは決まった戻り先だけ）、登録の回数に上限を付け、古い登録を片付ける）（I6・調査）。アプリの設定で AI ごとに「つなぐ」「書き込みを許可」「解除」を分ける。同意の画面には、どの AI からの接続か（戻り先のホスト名）を大きく出す。
- AI が足した記録をゴミ箱へ移すのは、作者が会話で頼んだ時だけの「依頼」にする（D48。NS SPEC-2.md の 15. と同じ考え方）。コネクタは受け取り箱に `target: 'trash'`・`payload: { id }`（そのコネクタで足した `by: 'connector'` の記録の id）で依頼を作るだけで、確かめてゴミ箱へ移すのはアプリ（19.4）。依頼の形と取り込みは今の版で入れ（データの形を段階1で固めるため。19.7）、ツールはコネクタと同じ段階6で作る。回数の上限などの細かい所は、その時に NS に倣って決める（開発）。

### 19.6 メールの内容をカレンダーに入れる使い方の下地

- DS はメールに直接つながない。Claude がメール（Claude 側のメールのコネクタ）を読み、DS のコネクタの `ds_add_items` で予定を足す流れを想定する（Q29・I6）。
- その時、メールの件名とリンクを `via` に入れてもらう（例「メール: 12/3 打ち合わせのご案内 / https://mail.google.com/…」）。DS は詳細の下の行と AI の札で `via` を見せる。

### 19.7 組み込みが難しくなる所（Q29 の「ここを過ぎると難しい所」）

- **段階1（データと同期）の完了**が境目。ここでデータの形（6.）とクラウドの置き方を固め、ほかの端末に記録が溜まり始めるため、後から項目の意味や id の決まりを変えると、全端末の記録を書き換える作業になる。
- そのため、AI 連携に要る物（`by`・`ai`・`via`、内容から作る id、受け取り箱、MIM の表を分けること、データの形の版）は、すべて段階1で入れる（この文書のとおり）。これが入っていれば、コネクタそのものは後のどの時点でも足せる（アクセスルールと Worker を足すだけ）。
- 段階1を終える前に、作者に「ここを過ぎると AI 連携の下地を変えにくい」と知らせ、19.2〜19.3 の決まりを確かめてもらってから固める（Q29・21。→22 の X3）。段階1の途中でデータの形を変えたくなった時も、作者に知らせてから決める。
