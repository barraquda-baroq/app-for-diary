# 手順5 持ち主の記録を作る

DS のクラウドのデータを読み書きできる「持ち主」のアカウントを、Firebase の画面で1つ記録します。
段階1（端末どうしの同期）の版を公開する前に、一度だけ行います。

- かかる時間: 約3分
- 使う物: PC のブラウザ（Chrome か Edge）
- いつ: 段階1の版を公開する前（Claude から「段階1の版ができました」と知らせが来て、手順3の「公開する」の npm run deploy を打つ前）。
  今すぐしてもかまいません。今の段階0のアプリは、この記録を使いません。
- 始める前に: https://console.firebase.google.com/ を、手順1でプロジェクトを作った Google アカウントで開き、diary-studio のプロジェクト（ID は diary-studio-35f4e）を押して開いておく。
  画面の左上にプロジェクトの名前が出ます。diary-studio になっていることを、先に必ず確かめてください。
  NS のプロジェクト（novel-studio-3352e）にも、同じ名前の持ち主の記録（config の中の owner）があります。NS の物は消したり直したりしないでください。NS の同期が止まります。

## なぜこの記録が要るのか

DS のアプリは、持ち主の記録を自分では作れない決まりにしてあります（Firestore のアクセスルール）。
持ち主の記録を作れるのは、Firebase の画面を開けるあなただけです。
こうしておくと、段階1の版を公開した後に、アプリの URL を知った人があなたより先にログインしても、その人が持ち主になることはありません。

記録が無いままだと、段階1の版のアプリは同期を始めずに、「持ち主の記録がまだありません（docs/manual/5-owner-record.md）」と出します。

## A. 自分のアカウントの「ユーザー UID」をコピーする

1. 左のメニューから「Authentication」を押して開く。
   「構築」や「セキュリティ」のまとまりの中にあります。見当たらない時は、画面の上の検索欄に Authentication と入れて、出てきた「Authentication」を押す。

2. 画面の上に並んだタブ（「ユーザー」「ログイン方法」「設定」など）の中から、「ユーザー」を押す。
   ログインしたことのある Google アカウントが、1行に1つずつ並んでいます。
   あなたは段階0（手順4）で DS にログインしているので、あなたのアカウントの行があります。

3. 左端の「ID」の列に、自分の Gmail のアドレス（手順4で DS にログインしたアカウント）が出ている行を探す。
   行が2つ以上ある時は、アドレスをよく見て、自分の行を選んでください。ほかの人の行があっても、その人は DS のデータを読めません（消さなくてかまいません）。
   自分の行が無い時は、手順4の B のとおりに PC で DS にログインしてから、ブラウザの読み込み直しのボタンを押して、この画面を出し直す。

4. その行のいちばん右の「ユーザー UID」の欄にマウスを乗せ、欄の右に出るコピーのボタン（四角が2枚重なった形）を押す。
   ユーザー UID は、英字と数字が28字ほど並んだ物です。
   コピーのボタンが出ない時は、UID の字の上でダブルクリックして選び、キーボードの Ctrl と C を一緒に押す（Mac は command と C）。

## B. Firestore に持ち主の記録を作る

1. 左のメニューから「Firestore Database」を押して開く。
   見当たらない時は、画面の上の検索欄に Firestore と入れて、出てきた「Firestore Database」を押す。

2. 画面の上に並んだタブの中から「データ」を押す。
   「パネル表示」と「クエリビルダー」の切り替えが出ている時は、「パネル表示」を押す。
   段階0ではまだ何も保存していないので、中はほとんど空です。

3. いちばん左の列の上にある「＋ コレクションを開始」を押す。
   「コレクションの開始」という小さな画面が開きます。

4. 「親のパス」の欄が「/」になっていることを確かめる。
   その下の「コレクション ID」の欄を押して config と入れ、右下の「次へ」を押す。
   すべて半角の小文字で入れ、前後に空白を入れないでください。

5. 「ドキュメント ID」の欄を押して owner と入れる。
   横の「自動 ID」のボタンは押さないでください（押すと、でたらめな長い名前が入ってしまいます）。
   これも半角の小文字です。

6. その下の1行目のフィールドを入れる。
   「フィールド」の欄に uid と入れる（半角の小文字）。
   「タイプ」の欄は string のままにする。
   「値」の欄を押して、A の 4 でコピーしたユーザー UID を貼り付ける（キーボードの Ctrl と V を一緒に押す。Mac は command と V）。
   値の前後に空白が入らないようにしてください。

7. 1行目の下の「＋ フィールドを追加」を押して、2行目のフィールドを入れる。
   「フィールド」の欄に createdAt と入れる（半角で、A だけ大文字。ほかは小文字）。
   「タイプ」の欄を押して、出てきた一覧から timestamp を押す。
   「値」の所に日付と時刻の欄が出るので、日付に今日の日付、時刻に今のおおよその時刻を入れる。
   これは「いつ作ったか」の控えです。時刻は何時でもかまいません。

8. 右下の「保存」を押す。
   小さな画面が閉じて、データの画面に戻ります。

## できたかの確かめ

1. Firestore の「データ」の画面で、いちばん左の列に config が出て、それを押すと、左から2つ目の列に owner が出ることを確かめる。
   出ていない時は、ブラウザの読み込み直しのボタンを押してから、もう一度見る。

2. owner を押す。いちばん右の列（左から3つ目の列）に、次の2行が出ていれば記録はできています。
   createdAt の行に、7 で入れた日時。
   uid の行に、A の 4 でコピーしたユーザー UID（"" で囲まれて出ます）。

3. いちばん右の列の uid の値と、Authentication の「ユーザー」の一覧の自分の行の「ユーザー UID」を見比べて、同じ字であることを確かめる。
   先頭の4字と最後の4字を比べるだけでもかまいません。

4. 段階1の版を公開した後に、PC で DS を開いてログインし、ヘッダーの右の同期の表示が「同期済み」になれば、持ち主として同期できています。

## 間違えた時の直し方

- コレクション ID を間違えた時（Config・configs・前後に空白など）:
  左から2つ目の列のいちばん上にある、そのコレクションの名前の右の「︙」（縦に並んだ3つの点）を押し、「コレクションを削除」を押す。
  確かめの欄にそのコレクションの名前をそのまま入れて、「削除」を押す。
  そのあと、B の 3 からやり直す。

- ドキュメント ID を間違えた時（owner でない名前になった、「自動 ID」を押して長いでたらめな名前になった、など）:
  左から2つ目の列で、その間違えた名前を押す。
  いちばん右の列のいちばん上にある、その名前の右の「︙」を押し、「ドキュメントを削除」を押して、「削除」を押す。
  そのあと、左から2つ目の列の上の「＋ ドキュメントを追加」を押し、B の 5 からやり直す（コレクション ID は config のままです）。

- フィールドの名前を間違えた時（uid が Uid になった、createdAt が createdat になった、など）:
  いちばん右の列のその行にマウスを乗せると、行の右に鉛筆のボタンとゴミ箱のボタンが出ます。
  ゴミ箱のボタンを押してその行を消し、確かめが出たら「削除」を押す。
  そのあと、いちばん右の列の上の「＋ フィールドを追加」を押して、B の 6 か 7 のとおりに入れ直し、「追加」を押す。

- 値やタイプを間違えた時（UID を貼り間違えた、ほかの人の UID を貼った、createdAt のタイプが string になった、など）:
  いちばん右の列のその行にマウスを乗せ、行の右に出る鉛筆のボタンを押す。
  値かタイプを直して、「更新」を押す。
  UID を直す時は、A の 3〜4 で自分の行の UID をもう一度コピーしてから貼り付ける。

- 間違えて NS のプロジェクト（novel-studio-3352e）で作業してしまった時:
  そこで何かを消したり直したりする前に、その画面を Claude に見せてください。
  NS の持ち主の記録を消したり直したりすると、NS の同期が止まります。

- 段階1の版を公開した後に、DS に「持ち主の記録がまだありません（docs/manual/5-owner-record.md）」と出た時:
  記録の場所か名前が違います。「できたかの確かめ」の 1〜2 のとおりに、config の中に owner があり、owner の中に uid の行があるかを見て、違う所を上のとおりに直す。
  直した後は、DS を閉じて開き直す。

- 段階1の版を公開した後に、DS に「このアカウントは Diary Studio の持ち主ではありません」と出た時:
  uid の値が、いまログインしているアカウントのユーザー UID と違います。
  ログインしたのが自分のアカウントなら、uid の値を、上の「値やタイプを間違えた時」のとおりに自分の UID に直して、DS を閉じて開き直す。
  別のアカウントでログインしていた時は、DS の［ログアウト］を押して、自分のアカウントでログインし直す。

## 気を付けること

- 作った config の中の owner は、消したり uid を書き換えたりしないでください。
  消すと、すべての端末で同期が止まります（「持ち主の記録がまだありません」と出ます。端末の中のデータは消えません）。
- 持ち主を別の Google アカウントに移したい時だけ、uid を新しいアカウントのユーザー UID に書き換えます（DEPLOY.md の「3. 持ち主のアカウント」）。
- ユーザー UID は合言葉ではありませんが、リポジトリやほかの人が見る所に書く必要はありません。
